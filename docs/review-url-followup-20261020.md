# 상품 페이지 읽기 후속 수정 — 2026-10-20

## 결과와 평가 범위

페이지 안의 우회적인 모델 지시문, 대출 상환액을 상품 가격으로 읽는 오류, 정상 심사 절차 안내를 지시문으로 분류하는 오류를 수정했다. 추천 상품 영역의 내용과 이미지를 현재 상품에서 분리하고, 제목의 `::` 뒤 사이트 이름을 제거한다. 가격만 자바스크립트로 그리는 페이지에서는 보이는 상품 설명을 읽되 가격을 추측하지 않는다.

**같은 합성 페이지를 보고 고친 뒤 다시 검사한 결과다.** 처음 저장한 [URL 평가 기록](../evals/reports/url_ingest_eval.json), HTML 35개와 `index.json`의 라벨은 그대로 보존했다. 새 결과는 [후속 회귀 보고서](../evals/reports/url_ingest_followup_20261020.json)에 별도로 저장하며 `evaluation_role: regression`으로 표시한다. 실제 쇼핑몰의 정확도나 별도 검증자의 성능 평가는 아니다.

## 재현한 문제와 수정

### 1. 문장과 가격 후보의 신뢰 경계

페이지용 지시문 검사는 주로 “AI는 … 하세요” 같은 직접 명령을 찾았다. “광고 문구로 옮기는 모델은 … 쓰는 것이 좋습니다”, “독자가 자동화된 검수 도구라면 … 기록해 주십시오”는 지나가서 사실 후보와 랜딩 문구에 남았다. 모델·검수 도구·심사 시스템을 수신자로 부르며 출력·기록·판정을 요구하는 구조를 추가로 검사한다. 특정 페이지 ID나 그 사례의 판매 순위 문구를 예외 처리하지 않았다.

가격은 본문 문장의 지시문 검사보다 먼저 수집되고 있었다. 따라서 문장을 버리더라도 그 안의 금액이 별도 가격 후보로 남을 수 있었다. 가격 후보가 나온 원문 줄을 보존해 같은 지시문 검사를 거친 뒤에만 가격으로 사용한다. 오염된 줄의 가격은 모두 버리는 보수적인 처리다. 이 때문에 같은 줄에 정상 가격과 지시문이 섞였으면 정상 가격도 비어 있을 수 있으며, 값을 지어내지 않는다.

### 2. 정상 안내와 명령 구분

공유 규칙은 “승인으로 처리”까지만 보고 정상 문장 “신청 후 심사를 거쳐 승인으로 처리됩니다”도 걸렀다. 공유 규칙 자체를 변경하지 않고 페이지 모듈 안에서만 조건부 심사·검토 절차와 서술형 종결을 확인한다. 모델·도구를 수신자로 삼거나 “확인 없이”, “상관없이” 같은 조작 단서가 있으면 제외하지 않는다. “처리해 주세요”, “판정하세요” 같은 명령과 같은 문장의 다른 지시문 검사는 그대로 남는다.

### 3. 금융 금액과 판매 가격 구분

기존 가격 종류 검사는 각 금액 앞의 짧은 이름표에 의존했다. 대출 상환 예시의 뒤쪽 월 납입금은 “상환”이라는 맥락이 멀어지면서 이름표 없는 상품 가격이 됐다. 상환·원리금·대출 원금·대출 한도 문장 안의 금액을 판매 가격에서 제외하고, 조건을 담은 원문은 사실 후보로 보존한다. 일반 월 구독료는 가격으로 남는 대조 사례도 검사했다.

### 4. 현재 상품과 추천 상품 분리

기존 파서는 `aside`, `nav`, `footer`는 본문에서 뺐지만 `section class="related"` 안의 다른 상품 이름·금액·이미지는 가져왔다. 명시적인 추천 영역 이름(`related`, `related-products`, `recommended-products`, `cross-sell` 등)을 기존 제외 경로에 연결했다. 하위 요소도 제외 상태를 상속하며 이미지는 동일한 경계를 따른다. 제외 영역 안의 지시문 여부는 상세 기록용으로 계속 검사한다. 임의의 모든 사이트 클래스 이름이나 추천 영역을 이해한다고 보장하지 않는다.

### 5. 가격을 읽지 못해도 보이는 설명 유지

이름·구매 버튼·보이는 본문이 있어도 가격과 구조화 정보가 모두 없으면 상품이 아니라고 보던 경우를 수정했다. 상품 제목과 구매 동작, 충분한 본문 또는 복수의 사양 문장이 있으면 읽을 수 있는 내용을 남긴다. 로그인 벽·빈 앱 화면·여러 상품·기사 단서는 기존대로 먼저 검사한다. 스크립트는 실행하거나 가격 데이터로 읽지 않는다. 기사에 구매 링크가 있다는 이유만으로 상품으로 바뀌지 않는 대조 검사도 포함했다.

제목의 이중 콜론 구분자도 기존 사이트 접미사 처리에 추가했다. `머그: 밤하늘 :: 소담몰`은 `머그: 밤하늘`로 남겨 상품명 안의 단일 콜론은 보존한다.

## 남은 범위

이번 14개 재검사에도 기대 구절 4개가 빠졌고, 작성자가 허용 목록에 넣지 않은 후보 15개가 있었다. ‘찬물에 손세탁’, ‘미끄럼 방지 그립’, ‘카드·계좌 연동은 선택’처럼 숫자가 없거나 기존 단서 목록과 다른 문장은 놓칠 수 있다. 허용 목록에 없다는 사실만으로 그 후보가 실제로 틀렸다고 확정하지는 않는다. 광고에 쓸 사실은 사용자가 원문을 보고 선택해야 한다.

스크립트 실행, 외부 CSS로만 숨긴 글의 판별, 모든 추천 영역의 의미 이해, 임의의 바꿔 쓴 지시문 탐지, 사람의 독립적인 라벨 검증은 제공하지 않는다. 구조화 정보의 여러 상품 해석과 사이트별 이름·가격 표기는 여전히 제한된 규칙으로 처리한다. 이 보완의 수치는 입력을 본 뒤 수정한 회귀 결과이며 새로운 실제 운영 성과로 쓰지 않는다.
