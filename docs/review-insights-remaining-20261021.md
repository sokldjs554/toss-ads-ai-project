# 성과 인사이트 잔여 한계 검토 — 2026-10-21

## 결과와 해석 범위

이전 기준 기간과 최근 표시 기간 **사이의 실제 관측을 버리던 경로**를 수정했다. 이전 기준 뒤의 관측도 변화 탐색에 사용하되, 최근 기간에서 같은 방향의 변화가 계속 관측될 때만 최근 사건으로 표시한다. 더 넓어진 탐색에는 추가 비교 보정을 적용하고, 기준선과 기울기의 추정 오차를 유지했다. 탐지 임계값, 최소 변화율, 표본 하한, 가설·액션 규칙과 생성기는 바꾸지 않았다.

이미 확인한 별도 합성 자료 80개의 회귀 결과는 **변화 탐지 33/35 → 34/35**, **정상 사례에 낸 알림 0/40 → 0/40**, **원인 top-1·top-3 29/32 → 30/32**, **허용 액션 적중 76/80 → 77/80**이다. `h26-p059`를 찾게 되었고 `h26-p077`은 여전히 놓친다. 첫 평가의 18/35와 후속 33/35 기록을 그대로 남겼으며, 이번 34/35를 새 맹검 평가라고 부르지 않는다.

수정 전에 명세와 첫 결과를 저장한 개발용 대조 48개에서는 지속된 국소 전환율 하락 탐지가 **4/12 → 5/12**였고, 정상·지속 추세·최근 기간 전에 회복된 사건 36개는 모두 알림이 없었다. 새 대조에서도 지속 하락 **7/12를 놓쳤다**. 이 수정은 관측을 버리는 한 경로를 해결하며, 약한 국소 변화를 충분히 탐지한다는 결론을 뒷받침하지 않는다.

## 두 누락의 재현과 원인

### 한 광고세트의 지속 하락: `h26-p059`

한 광고세트의 전환율이 낮아지는 사건이다. 기본 기준 기간은 2026-07-13부터 08-09까지 28일이고, 최근 표시 기간은 08-10부터 08-23까지 14일이다. 사건이 08-02에 시작하므로 기본 기준 기간에는 사건 뒤의 8일이 들어 있다. 이 광고세트의 기준 잡음은 로그 단위 0.4364까지 커지고, 실제 수준 변화 일부가 하루 -0.02754의 추세로 흡수된다.

기존 후속 엔진은 앞부분 기준 후보를 이미 검사했지만, 후보가 08-01에 끝나더라도 **08-02부터 08-09까지의 관측을 버린 채 08-10 이후만 비교**했다. 짧은 과거 기준에서 먼 최근 기간을 예측하는 불확실성 때문에, 한 세트의 약 50% 하락도 탐지 기준을 넘지 못했다.

아래는 같은 광고세트의 전환율을 비교한 진단이다. 표의 20일 기준은 원인 분리를 위한 설명용 선택이다. 제품의 `analyze`에는 정답 시작일·시나리오 ID·사건 종류를 전달하지 않으며, 날짜만으로 만든 모든 적격 기준 후보를 검사한다.

|---|---:|---:|---:|---:|---:|---:|
| 기존 28일 기준 | 28일 | 최근 14일 | 0.4364 | -0.02754 | 0.583 | 6.614 |

| 같은 20일 기준, 실제 전이 관측 포함 | 20일 | 기준 뒤 22일 | 0.1105 | 0 | 7.885 | 7.157 |

점수는 더 강해졌지만 필요한 점수도 **7.001에서 7.157로 높아졌다**. 임계값을 내려 사례를 통과시킨 결과가 아니다. 이 표의 진단 점수는 하루짜리 후보를 제외하고 최소 2일 구간을 검사한 값이며, 확률이나 유의확률이 아니다. 원문과 계산 설정은 [진단 JSON](../evals/reports/remaining-20261021/insights-diagnosis.json)에 있다.

제품은 날짜 후보를 탐색한 뒤 07-13부터 08-01까지를 기준으로 선택했다. 표시한 사건은 요청한 최근 기간인 **08-10부터 08-23까지**다. 이 구간의 해당 세트 전환율 변화는 약 -50.4%, 전체 전환율은 같은 예측 분자·분모로 계산할 때 약 -15.1%다. 전체 지표의 변화와 특정 세트의 변화를 같은 숫자로 섞지 않는다.

기존 원인 규칙은 이 결과에서 `landing_issue` 가설을 `supported`로 올리고 `check_landing`, `pause`를 제안한다. 액션 로직을 바꾸지는 않았다. `pause`는 기존 카탈로그의 랜딩 점검·신청 오류 확인 후 검토하는 제안이며, 보고서에는 확인 절차가 필요하고 광고를 실제로 멈추는 호출은 없다. `supported`는 원인 확정이나 인과 확률이 아니다.

### 기기 구분을 제거한 약한 집계 변화: `h26-p077`

이 사례는 기기별 클릭 비중이 달라지는 사건이지만 입력에서 기기 차원을 합쳤다. 직접적인 구성 변화 지표인 기기별 클릭 비중을 검사할 수 없고, 남은 집계 전환율 변화는 변동성과 기준선 불확실성에 비해 약하다.

기존 28일 기준에서 집계 전환율의 최대 여러 날 구간 점수는 **3.412**, 필요한 점수는 **5.651**이다. 사건 전 21일만 사용한 설명용 진단에서도 최근 구간 점수는 **1.814/6.100**, 중간 관측을 포함하면 **1.872/6.277**이었다. 현재 전체 표시 기간 전환율은 기대 대비 약 -14.2%지만, 그 변화율만으로 탐지 조건을 충족했다고 판단하지 않는다.

이 사례의 `detectable=true` 정답 가정과 재현율 분모를 그대로 유지했다. 이 변화는 여전히 탐지하지 못했으며, 제품은 `keep_watching`을 제안한다. 기존 요약의 “현재 비교로 모든 문제가 없다고 보장할 수는 없습니다” 문구도 유지한다. 추가 확인에는 기기·광고세트별 클릭과 전환, 더 긴 사건 전 이력, 전환 기록의 지연 여부가 필요하다. 기기 구분을 복구하지 않은 집계만으로 구성 변화와 랜딩 문제를 구별했다고 주장하지 않는다.

## 일반 수정과 보호 조건

수정은 [core/insight_engine.py](../core/insight_engine.py)의 탐지 경로에 한정했다. [core/performance.py](../core/performance.py)의 생성기와 입력 명세는 그대로다.

1. 직전 기준 기간 검사는 그대로 먼저 수행한다. 신호가 없을 때만 이전 기준 후보를 검사한다.
2. 이전 기준 후보 뒤부터 최근 표시 기간 끝까지의 실제 관측을 검사에 사용한다. 없는 날짜를 관측으로 채우지 않는다.
3. 기준선 추정 분산과 기울기 추정 분산을 포함한다. 확장 검사에서는 기준 기간의 추세 추정값이 0이어도 기울기 불확실성을 제거하지 않는다. 기준을 짧게 잘랐다는 이유만으로 추세를 확실한 0이라고 가정하지 않는다.
4. 확장 검사에서 발견한 구간은 최근 기간으로 잘라 표시한다. 최근 기간에 최소 3일의 실제 관측이 있어야 하고, 같은 방향의 표준화 잔차 중앙값이 기존 이웃 확장 기준인 2 이상이어야 한다. 최근 부분의 변화율도 기존 최소 변화율을 넘어야 한다. 과거의 강한 사건 하나와 현재의 작은 흔들림을 합쳐 최근 이상이라고 표시하지 않기 위한 조건이다.
5. 표기하는 변화율·최대 일별 잔차·일수는 잘라낸 최근 부분에서 계산한다. 탐지 점수에는 앞선 전이 관측이 포함될 수 있으므로, 기준 기간 설명에 “그 뒤부터 최근 기간까지의 관측값”을 함께 검사했다는 사실을 추가했다. 최근 첫날을 실제 시작일로 단정하지 않는 기존 안내와 검증도 유지한다.

비교 보정에서 계열 수를 `S`, 이전 기준 후보 수를 `K`, 최근 구간의 날짜 수를 `R`, 확장 검사의 날짜 수를 `L`이라 하면:

```text
직전 기준 검사: M = 2S
이전 기준 검사: M = 2KS × ceil([L(L+1)/2] / [R(R+1)/2])
적용 점수 기준: sqrt(h² + 2 log(M))
```

추가된 모든 연속 구간 수의 비율을 올림하여 비교 수에 반영한다. 예를 들어 `h26-p059`의 선택된 후보는 `M=672 → 2016`으로 강화된다. 기본 `H_SCORE=5.0`, 부분 집합 `SEG_H_SCORE=6.0`, 최소 변화율과 표본 하한은 바꾸지 않았다. 기준선 중앙값의 추정 분산 계수 `π/2`, 잡음 하한, 표본 잡음 하한도 그대로다.

이는 기존 정규 꼬리 상계 형태의 보정을 강화한 것이며 실제 광고 자료에서 오류율이 검증된 유의확률은 아니다. 짧은 이력, 계열 의존성, 추정된 잡음과 생성기 가정이 있으므로 `score`를 p-value나 원인이 맞을 확률로 읽으면 안 된다.

## 재현과 보존 확인

환경은 Python **3.11.17**이다. 시작 revision은 `4dce790`, 수정 전 엔진 지문은 `3185135f39763f7f`, 수정 후는 **`d5f751e9070f40f1`**이다. 이 검토에서는 실제 제공자 API를 호출하거나 원격 서비스를 변경하지 않았다. 실제 모델 문장 검증과 배포 결과는 통합 검토의 별도 기록에서 확인해야 한다.


대조 명세를 다시 실행하는 최소 명령:

```bash
.venv311/bin/python - <<'PY'
import json
from collections import defaultdict
from pathlib import Path
from core.performance import ScenarioSpec, generate
from core.insight_engine import analyze

source = Path('evals/reports/remaining-20261021/insights-contrasts-before.json')
summary = defaultdict(lambda: {'n': 0, 'alerts': 0})
for case in json.loads(source.read_text())['cases']:
    result = analyze(generate(ScenarioSpec.from_dict(case['spec'])))
    summary[case['family']]['n'] += 1
    summary[case['family']]['alerts'] += bool(result.incidents)
print(json.dumps(dict(summary), ensure_ascii=False, indent=2))
```
