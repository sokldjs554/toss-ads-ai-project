# 실제 사용자·정책 검수·업무 비교 준비

> 이 문서는 2026-10-23 당시 준비 기록입니다. 이후 사용자 승인·LIVE 계정별 한도·영속 저장과 본인1명·2건 사용 확인이 추가됐습니다. 새 진행은 [2026-10-24 실행 절차](operating-pilot-20261024/README.md)를 따르며, 아래 미완료/승인 필요 설명을 현재 상태로 해석하지 않습니다. 기존 입력·배정·미실행 측정 결과는 보존합니다.

아직 참여자 모집·연락·실험을 실행하지 않았다. 아래 절차는 사용자가 사람에게 전달할 자료다. 유료 모델 실행 승인을 포함하지 않는다.

## 먼저 필요한 최소 행동

1. 독립 검수자가 [정책 검수표](../evals/reports/strengthening-20261023/policy-human-review.csv)의 24개 원문/사실/정책 근거를 검토한다. 원래 모델 결과 열은 주지 않는다. 각자 라벨·원문 근거·적용 규칙·애매한 이유를 적고, 불일치는 토론 전 기록한다. 합의되지 않은 항목은 보류한다. 초안 정답을 바꾸면 새 버전과 변경 이유를 남기고 이번 고정 결과를 소급해서 고치지 않는다.
2. 기존 공동 검수 운영자가 본인 계정으로 로그인해 역할·배정 화면을 확인한다. 운영 자료를 변경하지 않고, 별도 허용된 시험 공간/합성 항목에서 저장 → 재접속 → 배포 후 동일 항목/감사 영수증 대조를 수행한다. 이 검증은 현재 미완료다. 계정 키·DB 비밀번호를 저장소/피드백에 넣지 않는다.
3. 실제 모델 파일럿을 원하면 사용할 정확한 모델·입력·호출 횟수·단가·예상 비용·최대 예약 한도를 새로 승인한다. 과거 $4/$10 평가 승인은 재사용하지 않는다. 이번 새 정책 24개는 무료로 규칙/대역만 실행했다. 사람 라벨 검수가 끝나기 전 새 유료 성능 비교를 먼저 실행하지 않는다.
4. 서버 키를 쓰는 제한 파일럿에는 운영자가 비밀 저장 경로로 32자 이상의 `PREFLIGHT_LIVE_ACCESS_TOKEN`과 제공자 키를 설정하고, 제공자 계정 지출 제한을 설정한다. 공개 모집에 필요한 사용자별 영속 quota·SSO·rate limit은 아직 없으므로 불특정 사용자 유료 운영으로 전환하지 않는다. 합성 입력만으로 DEMO 사용성 파일럿은 가능하다.

첫 독립 판단에는 검수표의 `draft_label` 열도 가린 사본을 사용한다. 각 검수자의 최초 판단을 저장한 뒤 AI 초안 정답과 대조한다. 초안을 미리 보고 검토했다면 그 사실을 기록하고 독립 맹검 정답으로 표현하지 않는다.

## 사람에게 전달할 무료 사용 절차

공개 DEMO에서 ‘커머스 쿠폰’ 예시를 실행한다. ‘실제 AI 호출 없음’ 표시를 확인한다. 남은 위반 구절과 사실을 대조한 뒤 문구를 직접 수정하고 재검사한다. 처음 결과·수정 횟수·최종 판정·알아보기 어려운 점을 기록한다. 사람 승인/저장 시험은 운영자가 지정한 격리 시험 공간에서만 한다. 공용 브라우저에 실제 광고주의 원문이나 계정 키를 남기지 않는다.

피드백 양식: 사용 모드(DEMO/승인된 실제 모델/과거 replay), 화면 빌드, 익명 참여자 ID, case ID, 시작/종료 시각, 최종 판단, 놓친 위반/잘못 반려, 수정 횟수, 혼란스러운 표시, 기대했던 다음 행동. 민감 원문 대신 합성 case ID를 사용한다. [빈 기록 CSV](evidence/strengthening-20261023/human-workflow-measurement.csv).

## 검수 시간 비교 파일럿 사전 절차

목적은 사람의 검수 시간과 오류를 함께 측정하는 것이다. 자동 실행 시간을 사람 시간 절감으로 환산하지 않는다. 초안 라벨을 검수한 사람은 측정 참여자가 되지 않도록 한다. 도구 제작자도 독립 사용자 집계에서 제외한다.

같은 정책 문서·같은 화면 크기·같은 사실 목록을 두 조건에 제공한다. 대조 조건은 도구 없이 원문과 정책/사실만 본다. Preflight 조건은 DEMO 또는 새 승인된 실제 모델 중 **사전에 한 가지를 고정**한다. 두 실행 모드의 사람 시간을 섞지 않는다. 각 조건 6개, 사례당 최대 2분, 별도 연습 2개로 약 30분 이내 파일럿이다. 연습에는 아래 평가 사례를 쓰지 않는다.

A/B는 서로 다른 6개 원문이며 각 정상 2개·검토 필요 4개로 맞춘다. [참여자 입력](evidence/strengthening-20261023/participant-inputs.json)에는 정답/수정안이 없다. 한 사람에게 동일 원문을 두 번 주지 않는다. 네 배정 순서는 다음과 같다.

| 배정 | 1기 | 2기 |
|---|---|---|
| 1 | 도구 없음 A | Preflight B |
| 2 | Preflight A | 도구 없음 B |
| 3 | 도구 없음 B | Preflight A |
| 4 | Preflight B | 도구 없음 A |

각 기의 사례 순서는 seed 20261023에서 배정별로 고정했다. 네 배정으로 순서·자료 영향을 분산시키지만 사례 난이도가 완벽히 같거나 학습 효과가 없어지는 것은 아니다. 4명은 절차 파일럿의 최소 균형 배정일 뿐 효과를 확정할 표본 크기가 아니다. 실제 인원은 사용자 모집 뒤 사전에 정하며 중간 결과가 좋다는 이유로 중단하지 않는다.

시계는 원문/사실을 처음 볼 때 시작하고 최종 제출 때 종료한다. 모델 대기시간을 포함한 총 경과 시간과 실제 작업 시간을 가능하면 별도로 기록한다. 타임아웃/포기/장애를 삭제하지 않고 상태와 상한 시간을 남긴다. 수정 횟수는 초안 뒤 문구를 바꿔 제출한 횟수다. 편집하지 않은 재클릭은 별도 중복 요청으로 기록한다.

조건을 모르는 별도 채점자가 검수된 정답을 기준으로 최종 결과의 놓친 위반과 정상 광고의 잘못된 반려를 판정한다. 조건 이름을 가리고 채점한다. 완료율·시간 중앙값/분포·놓친 위반/전체 위반·잘못 반려/정상·수정 횟수를 조건별로 함께 공개한다. 사례/참여자 단위 paired 결과와 불완료를 포함한다. 오류가 늘었는데 빠르다는 이유로 업무 개선으로 결론 내리지 않는다. 실제 결과 행은 현재 0개다.
