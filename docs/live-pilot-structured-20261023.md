## 원인·선택·실패 보존

v1은 JSON 형식만 강제하고 정책·상품 사실 인용을 모두 반환하라는 요구를 프롬프트에 두었다. 응답이 어느 종류의 인용을 빠뜨렸는지는 기존 원장이 저장하지 않으므로 3건의 누락 종류를 사후 추정하지 않는다. 검증을 느슨하게 하거나 빠진 인용을 코드가 대신 만들어 넣지 않는다.

v2는 `StructuredReview`의 정책 인용과 상품 인용을 각각 필수 필드로 두고, 각 ID의 enum을 이번 검색 결과의 해당 종류로 제한하는 strict JSON Schema를 제공자에게 전달한다. 서버에서도 종류·정확한 인용·원문 위치·모순 판정을 다시 검증한다. 실패해도 검색한 근거는 인증된 검토 화면에 보존한다. 성공 응답의 저장 형식은 기존 평탄한 `citations` 목록이라 v1 기록도 계속 읽을 수 있다. 프롬프트 버전은 `live-rag-tools-2`로 분리한다.

공식 [Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs)는 이 모델 스냅샷의 JSON Schema 지원, 모든 필드 required, 객체 additionalProperties=false 요구를 확인하는 데 사용했다. 스키마 일치는 인용의 의미·사실의 진실성·정책 정답을 입증하지 않는다.

수정 전 새 회귀 3개 실패/기존 13개 통과를 확인한 뒤, 수정 후 관련 엔진·게이트웨이·UI **26개 통과**. 추가 테스트는 스키마 필수 종류/검색 ID 제한, 사실을 정책 인용으로 바꾸는 응답의 보류, 실패 시 검색 근거 보존이다. 전체 CI·실제 v2 결과는 후속 실행으로 확정한다.

브라우저 검증에서 발견한 문제도 보존했다. 예시 반영 전 값 읽기는 실제 값 대기로, 이미 선택된 메뉴를 여는 문제는 기존 공동 검수의 키보드 선택 방식으로 고쳤다. 별도 실행에서는 HTTP 화면 로드/빈 화면 시간 초과가 있었으며 원인은 확정하지 않았다. 모델 요청 전 읽기 페이지 로드만 제한적으로 재시도한다. 모든 호출은 영속 중복 방지를 거치고 제공자 SDK 재시도는 0이다. 증거 폴더에는 run ID와 attempt를 함께 사용해 재실행 캡처 충돌을 막았다.
