# 실제 사람 파일럿 절차·기록표

대상은 합성 커머스 광고를 검토하는 개인 프로젝트 파일럿이다. 광고 게시·결제·고객 자료 입력은 하지 않는다. 자동 계정의 결과를 사람 사용으로 집계하지 않는다.

## 최소 수행 절차

1. [서버 LIVE 검토](https://preflight-toss-ads.onrender.com/?view=LIVE%20검토)에 접속한다. 별도 비공개 파일로 받은 **앱 접근키**로 로그인한다. OpenAI 키를 화면에 넣지 않는다. 화면 빌드와 시작 시각을 기록한다.
2. `rag-normal`을 불러온다. `RAG 정책 검토`를 선택하고 실제 LLM 실행을 누른다. 검색 문서 ID·정확한 인용·광고 원문을 대조한다. 인용이 원문에 있다고 해서 결론도 맞다고 가정하지 않는다. 판단과 사유를 저장하고 운영 기록 JSON을 다운로드한다.
3. 다른 광고 검토에서 `tools-number`를 불러온다. `도구 호출 수정·재검사`를 실행한다. 상품 근거 10%와 초기 문구 30%를 대조하고, 실제 도구 호출 패널에서 수정안·검사 결과를 확인한다. 최종 문구가 사실을 보존하는지 직접 검토한 뒤 결과와 사유를 저장한다. 해결되지 않은 결과는 승인하지 않는다.
4. 필요하면 `이 문구를 직접 수정하고 재검사`를 사용한다. 수정 전후 의미와 고지를 확인한다. 새 요청 ID를 기록한다. 같은 입력 재제출은 기존 결과 조회이며 새로운 모델 실험이 아니다.
5. 로그아웃하고 새 브라우저 세션에서 로그인해 내 기록 두 건을 다시 연다. 실행 시각·검토 결과·호출 수가 보존되는지 확인한다. 오류가 나면 시각·요청 ID·화면 메시지만 남긴다. 키나 개인정보가 있는 화면을 공유하지 않는다.

계정은 발급 후 30일 유효, 분당 신규 요청 3개, 계정 누적 예약 $0.50, 전체 $1.00이다. 요청당 $0.08 예약은 실제 청구액과 다르며 실패해도 자동 환급되지 않는다. 한도에 도달하면 추가 실행을 막는다. 제공자 장애나 미확인 결과는 DEMO로 바뀌지 않는다. 요청 진행 중 새로고침·반복 실행 대신 저장 기록을 확인한다.

## 참여자가 작성할 기록

| 항목 | 기록 |
|---|---|
| 참여 구분 | 실제 사람이 직접 수행 / 자동 실행 결과를 읽기만 함 |
| 수행 날짜·시작/종료 시각·시간대 | |
| 화면 빌드·접속 주소 | |
| RAG 요청 ID·검토 결과 | |
| 도구 경로 요청 ID·검토 결과 | |
| 인용이 원문과 일치하는가 / 결론을 실제로 뒷받침하는가 | 별도로 판단 |
| 수정으로 사실·조건·고지가 빠지거나 바뀌었는가 | |
| 놓친 위반 / 정상인데 잘못 지적한 내용 | 원문 구절·정책 ID·판단 이유 |
| 직접 수정 횟수·부모/자식 요청 ID | |
| 재접속 후 보존 여부 | |
| 실패·중단 시각·요청 ID·대응·해결 여부 | |
| 전달한 JSON 파일명 | |

접근키·계정 생성만으로 사람 참여를 확인하지 않는다. 저장된 `person_unverified` 감사 기록과 위의 직접 수행 확인을 함께 대조한 뒤 참여자 수와 작업 수를 집계한다. 두 경로 1회씩 사용해도 장기 운영·상용 고객·팀 협업 효과·시간 절감을 입증하지는 않는다.

## 시간 개선을 측정하려면

이 절차의 실행 시간은 운영 확인용이다. 시간 절감 주장은 별도의 비교 실험이 필요하다. 동일 난이도의 서로 다른 광고 묶음 A/B를 준비하고, 절반은 A를 도구 없이 → B를 Preflight로, 나머지는 B를 Preflight로 → A를 도구 없이 수행한다. 정답·채점 기준은 먼저 고정하고 작업 완료 전 공개하지 않는다. 사람이 시작/완료 시간을 기록하고 놓친 위반·잘못 반려한 정상 광고·수정 횟수를 같은 기준으로 채점한다. 인원·순서·원자료를 보존하며 자동 브라우저/API 지연을 사람 검수 시간으로 바꾸어 쓰지 않는다.
