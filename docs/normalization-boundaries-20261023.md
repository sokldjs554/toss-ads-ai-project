# 정규화 경계 과탐 회귀 수정 (2026-10-23)

## 재현과 원인

기준 `main`: `7b27a0e7689d4ee1319240f987d353cbac4a2d83`. 해당 소스의 `scan()`에서 아래 결과를 재현했다. `tight`가 한글 사이 공백·기호를 제거하면서 서로 다른 단어의 중간 조각을 붙였다. `lexical._matches()`가 이 일치를 그대로 받아 `TA-RESTRICTED-01/block`을 만들고, `adjudicator.decide()`의 결정론 block 우선 규칙이 REJECT로 확정했다. 원문 복원 자체는 정상이라 잘못된 일치 구간인 “폰! 지”를 정확히 표시하고 있었다.

| 동일 입력 | 수정 전 TA-RESTRICTED-01 | 수정 후 TA-RESTRICTED-01 |
|---|---|---|
| 쿠폰! 지금 확인하세요 | block, “폰! 지”, [1,5) | 없음 |
| 쿠폰 지금 확인하세요 | block, “폰 지”, [1,4) | 없음 |
| 쿠폰. 지금 확인하세요 | block, “폰. 지”, [1,5) | 없음 |
| 쿠폰을 지금 확인하세요 | 없음 | 없음 |
| 폰지 사기 | block, “폰지”, [0,2) | 동일 |
| 폰! 지 사기 | block, “폰! 지”, [0,4) | 동일 |

인덱스는 Python 문자열의 0 기반 반열린 구간이다. 전체 광고 “업계 최저 OO몰 가을 쿠폰! 지금 아니면 못 받는 조건”에서 잘못된 [14,18)만 사라진다. `TA-SUPERLATIVE-01`(업계 최저), `TA-URGENCY-01`(지금 아니면)은 유지된다. 실제 커머스 예시의 세 번째 광고안은 랜딩·근거·길이 위반도 남아 DEMO에서 REJECT → REVISE이다. 무조건 승인으로 바꾸지 않는다.

## 수정 기준과 한국어 경계

- NFKC, 제로폭 제거, 한자 접기, loose/tight 생성, 정책 YAML은 유지한다.
- `Surface.loose_indices`가 tight 문자와 loose 문자 위치를 연결한다. `src` 원문 인덱스 맵과 원문 인용 방식은 바꾸지 않는다.
- tight 후보가 **내부 구분자 삭제로 만들어졌고, 양 끝 모두 서로 다른 원문 영숫자·한글 덩어리의 중간**이면 결정론 일치에서 제외한다. “쿠[폰! 지]금”, “최[다 단계]별”, “매[일 수]령”을 같은 기준으로 처리한다. 쿠폰 예외 목록은 없다.
- 한쪽 끝이라도 단어 경계인 `폰 지`, `폰.지`, `폰 지사기`, `신종폰 지`는 계속 탐지한다. 연속된 `신종폰지사기`, 제로폭·NUL로 나눈 표기도 유지한다.
- 모든 패턴에 `\b`를 붙이면 한국어 조사·어미·합성어와 분리 우회를 놓칠 수 있다. 따라서 기존 일치 전체에 단어 경계를 강제하지 않고, tight가 새로 만든 부분 일치의 증거만 판단한다.
- 길이 비교와 양 끝 확인은 후보당 O(1), 추가 인덱스 공간과 생성 시간은 입력 길이에 비례한다. 기존 긴 기호 덩어리 처리도 유지한다.

## 의도적 한계와 애매한 사례

형태소 분석이나 문맥 의미 판별이 아니다. `쿠폰 지`처럼 한쪽 끝만 단어 경계인 애매한 표현은 여전히 block이다. 반대로 `신종폰 지사기`처럼 **양 끝 모두 다른 단어 내부에 묻힌 실제 우회**는 이 어휘 규칙만으로 확정하지 않는다. 의미 검토 단계와 자동 확정 불가 시 사람 검토가 필요하며, DEMO의 규칙 기반 대역이 실제 모델의 의미 탐지력을 보장하지 않는다. 제로폭만으로 연결한 정상 단어의 부분 일치 과탐, 원래 연속된 동음·합성어의 뜻 구별도 이번 수정의 해결 범위가 아니다. 이 경계 선택을 “모든 과탐 제거” 또는 “모든 우회 탐지”로 표현하지 않는다.

## 공유 경로와 회귀 검증

`scan()`을 쓰는 입력 인터셉트, 출력 검사, 인젝션, 원문 판정, 직접 재검사, 자동 수정안 재검사가 같은 필터를 사용한다. normalize의 표면 문자열은 유지하므로 loose 원문 인용 복원, URL 읽기의 별도 패턴 검사, 업종 사전라벨링의 직접 표면 사용은 바뀌지 않는다. 저장·계정·권한 코드는 수정하지 않았다.

`tests/test_normalization_boundaries.py` 35개: 정상 표현 9개, 실제 금지·우회와 원문 위치 11개, 한국어 접미·보수적 경계 사례 5개, 다른 규칙 우회 5개, 뒤에 나오는 실제 금지어 복원 1개, 최종 판정/예시/두 재검사 경로 4개. 수정 전 **12 실패·23 통과**, 수정 후 **35 통과·0 실패·0 skip**를 확인했다. 관련 8개 테스트 파일은 **177 통과·0 실패·0 skip**였다. 이는 과거 4,396개 기록을 재사용한 수치가 아니다.

기존 `test_failed_rewrite_not_shown_on_reject_and_revise_paths`가 커머스의 잘못된 폰지 탐지에 기대어 REJECT 분기를 만들고 있었음도 발견했다. 이제 생성 응답 fixture에 실제 `TA-COMPARE-01` block 문구를 넣어 REJECT와 REVISE 두 경로 모두에서 재검사 실패 수정안을 숨기는 기존 계약을 유지한다. 기대 판정 집합을 줄이지 않았다.

로컬 전체 pytest는 설치되지 않은 Streamlit 때문에 수집 단계 19 오류로 중단했다. 전체 통과로 계산하지 않는다. 전체 회귀·PostgreSQL·브라우저 저장 테스트와 평가 게이트의 확정 결과는 **변경 커밋의 [CI 실행](https://github.com/sokldjs554/toss-ads-ai-project/actions/workflows/ci.yml)**에서 확인한다. 테스트 수는 해당 실행 로그의 실제 passed/failed/skipped를 사용하며 PostgreSQL 선행 게이트의 중복 실행 수를 더하지 않는다. 기존 평가 수치와 지속 하락 7/12 미탐은 변경하지 않는다.

## 공개 배포와 브라우저 증거

기존 Pages workflow가 같은 Python 소스를 `app/src.zip`에 넣고 Render의 기존 Docker 배포도 같은 저장소를 사용한다. 소스 공유는 배포 완료의 증거와 다르다. [normalization-public-ui](https://github.com/sokldjs554/toss-ads-ai-project/actions/workflows/normalization-public-ui.yml)는 Pages 배포 성공 후 해당 커밋으로 실행하며 다음을 실제 Chromium에서 검사한다.

1. 공개 src.zip의 빌드와 normalize/lexical/정책/최종 판정/재검사 소스가 checkout과 일치.
2. 두 공개 사이트의 화면 빌드가 해당 커밋과 일치.
3. 커머스 예시 실행, 잘못된 금지 업종 표시 없음, 다른 위반 및 수정 필요 유지.
4. 직접 편집한 정상 쿠폰의 재검사 통과, 실제 `폰! 지 사기` 재검사 반려와 정확한 표시.
5. 각 단계의 실제 PNG·DOM·검사 결과 JSON을 Actions artifact에 저장.

유료 실행 버튼, 공동 검수 로그인·저장·계정 변경은 수행하지 않는다. “예시로 바로 실행”과 그 DEMO 재검사만 이용하며 모델 API 요청도 브라우저에서 차단한다. 인증 뒤 저장·권한의 공개 실사용 검증은 이번 브라우저 확인 범위가 아니다. workflow의 실패 또는 미실행을 배포 검증 완료로 보고하지 않는다.

## 지원 문서에 반영할 사실

자기소개서 마지막 절과 포트폴리오 8쪽에는 “최종 검수에서 정규화가 다른 단어의 조각을 연결해 금지 업종으로 반려하는 문제를 재현하고, 원문 경계 기반 검증과 실패부터 확인한 회귀 테스트로 수정했다”를 사용할 수 있다. 전체 CI 수, 배포 커밋, 브라우저 조작 완료 여부는 이번 실행의 실제 결과를 붙인다. 기존 평가 정확도·사람 응답 일치·지속 하락 미탐이 개선됐다는 문구로 바꾸지 않는다. 의미 검토·사람 확인과 유료 호출 0의 범위를 구분한다.
