# 성과 인사이트 검토·수정 기록 — 2026-10-20

## 범위와 근거

`docs/FEATURES.md` 5절과 현재 코드·테스트를 기준으로 성과 데이터, 진단 엔진, 보고서 문장 검증, 평가 CLI, 성과 화면을 확인했다. 이전 Claude 검토의 상세 결과는 저장소에 없으므로 그 결과를 재구성하거나 완료했다고 주장하지 않는다. 아래 문제는 이번 작업에서 직접 재현했다.

수정한 파일은 `core/insight_engine.py`, `evals/insights_eval.py`, `tests/test_insights_eval.py`, 새 `tests/test_insights_reporting_regressions.py`이다. `core/performance.py`, `agents/insights.py`, `ui/performance_view.py`는 읽고 기존 테스트로 확인했으며 수정하지 않았다.

## 재현한 문제와 수정

1. **비용 기여도 합계가 틀림.** 42일 동안 매일 노출 10,000회, 클릭 1,000회, 광고비 100,000원으로 두고, 기준 28일의 전환을 하루 5건, 최근 14일은 하루 1건으로 두면 전환율 기여도 98.3%와 클릭당 비용 기여도 0.0%를 출력하면서 합은 100%라고 설명했다. 원인은 탐지용 가짜 관측을 더한 전환율과 실제 전환당 비용을 섞어 로그 분해한 것이다. 보고 근거의 비율은 실제 합계로 계산하도록 고쳤다. 클릭당 비용이 절반으로 줄어 하락 효과가 상쇄되는 경우의 음수 기여도도 같은 항등식으로 확인했다.
2. **전환 0건에서 전환당 비용을 만들어 냄.** 위 최근 기간의 전환을 0건으로 두면 실제 전환당 비용은 정의되지 않는데, 보고서와 카드가 2,800,000원 및 13,900% 상승을 표시했다. 이제 전환 0건에서는 비용을 계산할 수 없다는 근거 문장을 표시하고, 해당 요약 카드는 제외하며 차트는 값이 없는 구간으로 남긴다. 실제 전환율은 0이다. 광고비 0원에 전환이 있는 입력은 전환당 비용 0원으로 표시하고 로그 분해를 생략한다.
3. **동결 지문 누락·충돌을 놓침.** 평가가 비어 있는 지문을 버리고 정렬된 지문 중 첫 값만 비교해 누락 또는 서로 다른 지문이 통과할 수 있었다. 이제 모든 최종 확인용 시나리오의 지문 존재·일치와 데이터셋 메타데이터의 지문 일치를 검사한다. 명시적 회귀 모드에서도 이 검사는 우회되지 않는다.
4. **회귀 평가가 새 결과를 자기 기준으로 삼음.** `--gate --out`이 기준 보고서와 같은 경로에 쓰는 경우, 쓰기 이후 기준을 읽어 지표가 0.2 떨어져도 통과했다. 기준은 쓰기 전에 읽는다. 보존된 과거 보고서 경로는 어떤 CLI 모드에서도 덮어쓰지 못하게 하고 별도 출력 경로를 안내한다.

탐지의 요일 보정, 임계값, 기본 통계 평활화와 액션 가드는 변경하지 않았다. 관측 근거·요약 카드·차트의 실제 값은 평활화하지 않는다. 이 때문에 소스 지문이 바뀌었다는 사실을 숨기지 않는다.

## 과거 평가의 보존과 현재 회귀 검사

- 원래 보고서 `evals/reports/insights_controlled.json`와 데이터 `evals/datasets/perf_scenarios.jsonl`는 바꾸지 않았다. 마지막 확인에서 두 파일에 `git diff`가 없었다.
- 과거 엔진 지문은 `fe53a3d060030913`, 현재 엔진 지문은 `83a47efd048e8ad3`, 데이터셋 지문은 `add5a3a6fcbb6127`이다.
- 보존된 53개 시나리오의 현재 평가 결과는 과거 보고서와 시나리오별 결과 및 양쪽 분할의 전체 집계가 같다. 탐지·진단 순위/확신·액션·금지 액션·보고서 검사·주입 시험 결과를 비교했다. 이는 수정 전후 회귀 확인이며 새 독립 평가가 아니다.
- 기존 최종 확인용의 정상 대조 4개 중 2개에서 이상을 낸 결과, 단일 원인 1순위 9/10, 동시 원인 한계 등은 그대로 남겼다. 라벨, 시드, 시나리오, 정답, 탐지 임계값을 조정하지 않았다.
- 현재 보고서에는 `engine_changed_after_holdout: true`, `holdout_role: "regression"`가 기록된다. 과거 관찰 목록은 처음 평가했을 때의 기록임을 따로 명시한다.
- 기본 `--gate`는 변경된 엔진을 여전히 거부한다. 이미 본 데이터를 회귀 검사로 쓰려면 `--regression`을 명시한다. 이 모드는 지문 누락·충돌, 금지 액션, 근거 없는 숫자 및 수치 회귀를 허용하지 않는다.

현재 전체 평가와 별도 결과 저장 명령:

```bash
.venv311/bin/python -m evals.insights_eval --split all --gate --regression --out evals/reports/insights_regression.json
```

동일 명령에서 `--regression`을 빼면 동결 이후 엔진 변경 때문에 종료 코드 1이 되는 것이 의도된 동작이다. 과거 보고서 경로를 `--out`에 지정하면 종료 코드 2로 거부한다.

## 검증 기록

수정 전에 실제 실패를 확인한 뒤 최소 수정했다.

- 보고 수치 회귀 5건: 비용 기여도 두 경우, 전환 0건 보고서, 카드·차트 실제 값, 광고비 0원 보고서가 모두 실패한 뒤 통과했다.
- 평가 무결성 4건: 지문 누락, 서로 다른 지문, 메타데이터 충돌, 출력 전에 기준을 읽는 검사가 모두 실패한 뒤 통과했다.
- 회귀 모드는 미지원 인수/함수 인수로 실패하는 것을 확인한 뒤 구현했고, 과거 보고서 경로 보호는 별도 오류 이유를 확인했다. 개발용 분할만 출력하는 경우도 과거 기록을 덮어쓸 수 있었음을 추가 재현한 뒤 막았다.
- 기존 동결·최신성 테스트 3건은 보고 계산 수정으로 의도대로 실패했다. 이를 원래 지문과 과거 기록 보존, 현재 결과의 회귀 동등성, 명시적 회귀 CLI 계약으로 변경했다. 현재 지문으로 과거 지문을 갈아 끼우지 않았다.

```bash

```

**결과: Python 3.11.17, 266 passed in 17.28s.** Streamlit AppTest 화면 검사를 포함한다. 관련 파일의 `git diff --check`도 통과했다. 프로젝트 전체 테스트·외부 배포·브라우저 E2E는 통합 담당자가 수행한다.

## 한계

실제 광고 데이터, 유료 LLM·비전 제공자, 외부 API는 호출하지 않았다. 합성 시나리오와 기존 가짜 제공자만 사용했다. 보고서 문장 검사의 정확도나 원인 판별의 실서비스 성능을 새롭게 입증한 작업이 아니다. 미지의 원인 조합을 추가 탐색하거나 기존 최종 확인용의 나쁜 숫자를 개선하는 작업은 하지 않았다.
