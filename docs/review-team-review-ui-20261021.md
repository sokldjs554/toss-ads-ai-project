# 공동 검수 UI 구현·검증 — 2026-10-21

## 범위와 결과

`ui/team_review_view.py`를 추가하고 `ui/ops_hub.py`에 **공동 검수** 탭을 연결했다. 이 UI는 서버의 `PostgresTeamStore.execute()`만 사용하며, 역할·계정 ID·점유·검토·조정·내보내기 자격은 `ops/team_review.py`가 매 요청에서 확인한다. 로컬 검수 대기열의 이름 입력이나 저장본 업로드를 공동 검수에 연결하지 않는다.

브라우저 실행판은 서버 운영 화면 링크만 제공한다. 서버 실행판은 연결 설정 유무, 비밀번호형 접근키 입력, 역할별 작업, 로그아웃을 제공한다. 접근키와 미확인 요청은 현재 Streamlit 세션에만 보관한다. 로그아웃 또는 인증 실패 시 `team_` 세션 상태를 모두 삭제한다.

이 문서의 검증은 모델 호출과 외부 저장 없이 실행한 UI·계약 회귀다. 실제 PostgreSQL 연결, 동시 트랜잭션, 서버 배포, 실명 확인, 독립적인 실제 검수 참여는 각각 별도 증거가 필요하다.

## 역할별 화면

| 역할·환경 | 제공하는 작업 | 데이터 경계 |
|---|---|---|
| 브라우저 실행판 | `https://preflight-toss-ads.onrender.com/?view=운영` 열기 | 데이터베이스 설정 조회와 키 입력을 시작하지 않는다. |
| 검수자 | 다음 광고 배정, 본인 배정 광고 보기, 판정·기준·인용·이유 제출, 반납 | 서버의 비공개 검수용 응답에 있는 광고·근거·랜딩 내용만 표시한다. 다른 검수자의 판정, 사전 제안, 전체 대기열, 계정 목록, 내보내기는 표시하지 않는다. 제출 후에도 다른 판정을 공개하지 않는다. |
| 조정자 | 판정이 갈린 광고와 검토 이유 확인, 조정 결과 저장, 완료 결과 내보내기 | 서버가 허용한 갈림 목록만 표시한다. 조정 이유와 인용을 사전 검증하고, 서버가 계정 ID를 결정한다. |
| 관리자 | 검수자·조정자 계정 발급, 다른 계정의 키 재발급·활성/비활성화, 기존 광고 작업 결과 추가, 광고 직접 입력, 내보내기 | 관리자 본인의 키 재발급은 이 UI에서 제공하지 않는다. 접근키 원문은 명령 payload에 넣지 않고 해시만 전달한다. |

기존 광고 작업에서는 담당자 확인 대상만 서버 대기열에 추가한다. 직접 입력은 광고마다 고유한 출처 ID를 받는다. 두 입력 경로 모두 합성 예시 표시가 기본값이다. 실제 광고로 수집한 경우 사용자가 표시를 해제한다.

판정은 `점검 통과`, `수정 필요`, `게재 불가`로 표시하고 자동 선택하지 않는다. 적용 기준은 제목으로 선택한다. 인용이 광고에 실제로 있는지, 판정과 기준이 일관적인지, 조정 이유가 충분한지 검증한 뒤 전송한다. 최종 권한과 입력 검증은 서버가 다시 수행한다.

## 저장 응답과 재시도 계약

모든 변경 요청은 전송 전에 `{action, payload, request_id}`를 세션에 고정한다. payload는 복사하고 UUID는 한 번만 생성한다. 미확인 요청이 있는 동안 다른 변경 폼을 표시하지 않는다. 자동 재전송은 하지 않으며 사용자가 **같은 요청으로 저장 결과 확인**을 누르면 같은 UUID와 같은 payload를 보낸다.

| 결과 | 세션 처리 | 다음 화면 |
|---|---|---|
| 성공 응답 | pending을 지우고 서버 응답에 따른 안내를 준비한다. 기존 내보내기 결과는 폐기한다. | 최신 서버 정보를 조회해 다음 작업을 제공한다. |
| `TeamReviewError`, `ValidationError`, `QueueError`, `AnnotationRejected` | 원자적으로 거절된 요청이므로 pending을 지운다. 키 발급 준비 중이었다면 해당 키 원문도 지운다. | 이유를 표시하고 입력을 고칠 수 있게 한다. 권한은 다음 서버 조회에서도 확인한다. |
| `AuthenticationError` | 키·pending·입력·내보내기 등 공동 검수 세션 상태를 지운다. | 다시 키를 입력할 수 있다. 재발급 키가 같은 계정에 속하면 서버의 본인 배정 목록을 다시 확인할 수 있다. |
| `StorageUnavailable`, `StorageBusy`, 전송 예외 또는 미확인 예외 | 저장 여부를 단정하지 않는다. 원래 pending과 발급 준비 키를 유지한다. | 같은 요청 재확인과 로그아웃을 제공한다. 예외 원문·연결 문자열·자격증명은 표시하지 않는다. |

로그아웃은 미확인 요청 중에도 가능하다. 이 경우 세션에만 있던 재시도 요청과 아직 전달하지 못한 발급 키는 사라진다는 점을 화면에 알린다. 데이터베이스에 저장된 결과는 삭제하지 않는다. 계정 발급 결과를 확인하기 전에 세션을 잃었다면 관리자는 계정 목록을 확인하고 해당 계정의 키를 다시 발급해야 한다.

### 접근키 표시

새 접근키는 서버의 `new_access_key()`로 생성하고 `key_digest()` 결과만 변경 payload에 포함한다. 원문은 별도의 세션 값으로만 보관한다. 발급·재발급 성공을 확인한 뒤 관리자 화면에 한 번 표시하고 그 즉시 세션에서 꺼낸다. 다음 화면 갱신에서 다시 표시하지 않는다. 재발급 대상에서 관리자를 제외해 본인 키가 바뀌면서 재시도 인증을 잃는 경우를 UI 범위에서 만들지 않는다.

원문 접근키는 명령 기록, 서버 저장 상태, 추적 기록, 내보내기 파일에 추가하지 않는다. 기존 키 입력은 비밀번호형 필드다. 자동으로 누군가에게 전달하거나 메시지를 보내는 기능은 없다.

## 내보내기 의미

내보내기는 서버가 완료로 인정한 평가셋 후보만 요청한다. 합성 예시는 기본적으로 제외한다. 포함 여부를 바꾸면 이전 범위의 다운로드를 표시하지 않고 새 조회를 요구한다.

화면과 JSONL 머리말에 다음 의미를 보존한다.

- 서로 다른 계정의 기록이 있어도 실제 참여자와 독립 검수 여부는 별도 확인이 필요하다.
- `identity_verified=false`, `independence_verified=false`를 기록한다.
- `synthetic_included`를 기록하고 합성 포함 파일 이름을 구별한다.

계정 두 개를 만들거나 합성 예시를 검토하는 행위를 실제 독립 사람 검수의 완료 수로 올리지 않는다.

## 재현과 검증

UI 테스트는 `MemoryStore`가 실제 `team_review.execute()`를 호출하도록 구성했다. 서버 상태 전이를 적용한 **뒤** 응답을 잃게 하고, 같은 요청 재시도가 저장된 결과를 회수하는지 확인한다. 시간과 계정을 고정하고 실제 광고 배정·제출·조정·내보내기를 실행한다.

```bash
.venv311/bin/python -m pytest -o addopts='' -q \
  tests/test_team_review_ui.py tests/test_team_review.py \
  tests/test_team_review_adversarial.py \
  tests/test_ops_view.py tests/test_labeling_ui.py \
  tests/test_review_persistence_ui.py
```

결과: **115 passed, 3 skipped in 15.00s**. 이 중 새 공동 검수 UI 테스트는 **22개**다. 건너뛴 3개는 이 실행 환경에 테스트용 PostgreSQL 연결이 설정되지 않아 실행하지 않은 데이터베이스 통합 검사다. 따라서 이 결과를 실제 데이터베이스 검증 완료로 세지 않는다.

검증 항목:

- 미설정·브라우저 환경에서 키 입력과 DB 접근을 시작하지 않음.
- 비밀번호형 로그인, 서버 역할 적용, 로그아웃 시 공동 검수 세션만 삭제.
- 앞선 검수자의 실제 판정 이유가 두 번째 검수자의 화면에 제출 전후 모두 나타나지 않음.
- claim·submit·release가 저장 후 응답을 잃어도 동일 요청 재시도로 한 번만 적용됨.
- 명확한 입력·권한·스키마·대기열 거절은 수정할 수 있고, 저장 응답 미확인 상태만 유지함.
- 미확인 상태에서 화면 갱신이 자동 전송을 만들지 않고 로그아웃이 가능함.
- 계정 발급·타인 키 재발급 응답 유실 후 같은 요청으로 확인하며, 원문 키가 payload·서버 상태·명령 기록에 없고 한 번만 표시됨.
- 직접 입력과 기존 광고 작업 추가, 다른 계정 비활성화, 관리자 본인 키 재발급 제외.
- 실제로 갈린 두 판정을 제3 조정 계정이 조정한 뒤 내보냄. 결과와 파일 머리말이 신원·독립성 미확인 상태를 유지함.
- 예외 원문에 넣은 가짜 연결 문자열이 UI에 나타나지 않음.
- 기존 두 탭의 순서를 유지하며 공동 검수 탭에 현재 실행 결과를 전달함.

`git diff --check`도 통과했다. 실제 브라우저에서의 화면 크기별 시각 검수와 배포된 PostgreSQL에 대한 검증은 이 AppTest 결과에 포함하지 않는다.

## 남은 운영 범위

최초 관리자 발급, 데이터베이스 연결과 마이그레이션, 서버 배포, 관리자 본인 키의 만료 전 교체·분실 후 복구는 서버 운영 절차다. 현재 UI는 이러한 작업을 자동 실행하지 않는다. 관리자 키의 만료·복구 절차를 마련한 뒤 실제 담당자에게 키를 배포해야 한다.

세션 종료 후 미확인 요청 자체를 복구하는 브라우저 영구 저장 기능은 없다. 서버에 완료된 검토와 계정은 남고 새 로그인으로 조회하지만, 아직 확정되지 않은 폼 입력과 발급 준비 키는 세션과 함께 사라진다.

변경 파일: `ui/team_review_view.py`, `ui/ops_hub.py`, `tests/test_team_review_ui.py`, 이 문서. 서버 명령·저장 어댑터·의존성 변경은 별도 작업 범위다.
