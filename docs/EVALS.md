# 평가

## 데이터셋 (`evals/datasets/`)

| 파일 | 내용 | 라벨 |
|---|---|---|
| `golden.jsonl` | 53건. 슬라이스: `clear`(명백 위반) · `evasion`(표기 변형·패러프레이즈·부정문) · `injection` · `gray`(경계, 수정 요청) · `benign_scary`(무서운 단어가 있지만 괜찮음 — 오탐 측정) | APPROVE / REVISE / REJECT + 잡혀야 할 `rule_ids` |
| `redteam_seeds.jsonl` | 레드팀 시드 4건 (명백한 위반) | REJECT |
| `adversarial.jsonl` | 레드팀이 **뚫은** 변형을 수확한 회귀셋 (처음엔 비어 있다) | REJECT |

라벨은 '코드가 내야 할 판정' 이다. 같은 저자가 규칙과 라벨을 썼으므로 `golden` 의 수치는 일반화의 증거가 아니라 **회귀 감시용** 이다. 사람 라벨러·독립 작성자 셋은 다음 단계다.

## 지표 (`evals/metrics.py`)

| 지표 | 정의 | 왜 보나 |
|---|---|---|
| 위험 승인율 (unsafe_approve) | 라벨이 REVISE/REJECT 인 소재를 APPROVE 한 비율 | 가장 중요한 안전 지표. 0 이어야 한다 |
| 오탐율 (false_flag) | 라벨이 APPROVE 인 소재를 REVISE/REJECT 한 비율 | 과잉 반려는 광고주 이탈 |
| 커버리지 | 사람 검토로 넘기지 않고 자동 판정한 비율 | 전부 사람에게 넘기면 '안전' 하지만 쓸모없다 |
| 규칙별 P/R/F1 | finding 의 rule_id 집합 vs 라벨 rule_id 집합 (warn 제외) | 어느 규칙이 과·소탐하는지 |
| ECE / Brier / reliability diagram | 신뢰도 = P(판정이 맞음) 으로 보고 보정 측정 | '자신 있게 틀림'(FM-14) |
| 고신뢰 오류율 | 신뢰도 ≥ 0.8 인데 틀린 비율 + 사례 id | 임계값 τ 의 근거 |
| 커버리지 곡선 | τ 별 (커버리지, 위험 승인율, 오탐율) | "0% 위험 승인으로 몇 % 를 자동 처리할 수 있나" |

모든 비율에 분모와 Wilson 95% 구간을 붙인다. 53건에서는 한 건이 2~7%p 를 움직인다.

## 실행

```bash
python -m evals.run --dataset golden --no-llm            # 결정론 계층만 (네트워크 없음)
python -m evals.run --dataset golden                     # 심사 모델 포함 (키 없으면 demo 대역)
python -m evals.run --dataset golden --gate              # 기준선 대비 회귀 게이트 (CI)
python -m evals.run --redteam --harvest                  # 레드팀 → 뚫린 변형을 adversarial.jsonl 에 수확
```

## 회귀 게이트 (`evals/regression.py`)

정확도 평균이 아니라 **방향** 을 본다. 기준선 대비 위험 승인율이 조금이라도 오르면 실패, 오탐율 +5%p·사람 검토율 +15%p 초과면 실패, recall 1.0 이던 규칙이 떨어지면 경고. 기준선 파일은 모드별(`baseline_demo.json`, `baseline_deterministic_only.json`)이라 대역 결과와 실제 모델 결과가 섞이지 않는다.

### partial 모드에서 배운 것 (2026-10-16, 프롬프트 v2026.10.1)

- **위험 승인 0건.** 명백 위반·우회·인젝션·경계 슬라이스 모두에서 반려/수정이어야 할 소재를 승인하지 않았다.
- **오탐 5/14.** `benign_scary` 슬라이스에서 사실 그대로 쓴 소재(7일 무료 체험 후 월 19,900원 자동결제, 최저 연 4.5% ~ 최고 연 15.0%, 재테크 강의 + 성과 개인차 안내, 유산균 기능성 문구, 비교 대상 없는 '최초') 를 **신뢰도 0.80~0.85 로 REVISE** 했다. 모델이 자주 든 규칙은 `TA-OMISSION-01`(조건 생략) 6건으로 전부 오탐이었다 — 조건이 괄호·고지에 있어도 '생략' 으로 본 것이다.
- **보정.** reliability diagram 에서 0.8 구간(5건)의 실제 정답률이 0 이었다. ECE 0.14, 고신뢰 오류율 10.4%. 커버리지 곡선: τ=0.80 → 커버리지 91%·오탐 38%, **τ=0.90 → 커버리지 81%·오탐 0%·위험 승인 0%**. 이 모드에서 자동 판정 임계값은 0.90 이 맞다.
- **환각 인용 7건 / 5사례** (FM-04). 모델이 원문에 없는 구절을 인용했고, 인용 검증이 이를 warn 으로 내리고 신뢰도를 0.6 으로 깎아 3건이 사람 검토로 갔다. 검증이 없었다면 반려 근거가 됐을 것이다.
- **조치.** 프롬프트 v2026.10.2: '사실 목록의 숫자·조건을 그대로 쓴 소재는 과장이 아니다', '조건이 어디에든 있으면 TA-OMISSION-01 이 아니다', '위반 아닌 소재를 REVISE 로 올리는 것도 측정되는 오류다', '필수 고지는 결정론 검사가 판정했다'. 효과는 다음 live-eval 실행에서 같은 지표로 다시 잰다 — 프롬프트를 고친 뒤 재측정한 수치는 holdout 이 아니다.

### 1차 → 2차에서 바뀐 것 (같은 골든셋, holdout 아님)

| 지표 | 1차 | 2차 |
|---|---|---|
| 오탐 (benign_scary 14건) | 5 | 3 |
| 환각 인용 (FM-04) | 7건 / 5사례 | 3건 / 3사례 |
| ECE / Brier | 0.143 / 0.080 | 0.092 / 0.046 |
| 고신뢰(≥0.8) 오류 | 5/48 | 3/50 |
| 오탐 0%·위험 승인 0% 를 만족하는 최소 τ | 0.90 | 0.90 |
| τ=0.90 에서의 커버리지 | 81% | 89% |

사례별로 보면 G-064·G-067·G-072 가 REVISE(0.85) → APPROVE(0.95) 로 바뀌었고, G-060 은 HUMAN_REVIEW(환각 인용) → REVISE(0.85) 로 '다른 방식으로' 틀렸다.
남은 오탐 3건의 성격은 둘이다.
1. **G-060·G-071: 코드가 충족으로 확인한 고지를 모델이 '누락' 이라 함.** 두 번의 실행에서 반복됐고 프롬프트로 막히지 않았다. 그래서 구조로 막았다 — 고지·근거·구조 계층은 결정론 코드가 완전하게 판정하므로, 모델이 그 계층 규칙으로 '없는 위반' 을 내면 버리고 FM-23 으로 기록한다(`agents/reviewer.py::DET_AUTHORITATIVE_LAYERS`). 모델은 이 계층에서 추가만 할 수 있고 뒤집을 수 없다.
2. **G-069: '최초' 가 들어간 정상 소재에 TA-OMISSION-01(조건 생략).** 두 실행 합쳐 TA-OMISSION-01 은 11번 나왔고 전부 오탐이었다. 다만 골든셋에 조건 생략 **양성** 사례가 없어 recall 은 측정되지 않았다. v1.1 에서 양성 2건(G-080·G-081, `semantic_only`)을 넣어 다음 실행부터 양쪽을 잰다. 심각도는 fix 로 둔다 — 조건 생략은 실제 반려 사유이고, 과잉 적용은 τ=0.90 이 사람 검토로 보낸다.

### 3차에서 배운 것

- FM-23 은 작동했다: G-060·G-071 의 모델 finding(고지 누락·근거 없음)이 전부 버려져 `predicted_rules=[]` 가 됐다. **그런데 판정은 REVISE 로 남았다.** 모델의 decision 을 '완화할 수 없다' 는 규칙만 있고, 근거가 사라졌을 때의 규칙이 없었기 때문이다. 조치: 근거 finding 이 하나도 남지 않은 REVISE/REJECT 는 `unsupported_decision` 으로 표시하고 adjudicator 가 사람 검토로 보낸다 — 근거 없는 판정은 어느 방향으로도 자동화하지 않는다. 3차 데이터에 적용하면 오탐 3→1, 사람 검토 1→3 이 된다 (다음 실행에서 실측).
- 조건 생략(TA-OMISSION-01) 양성 2건(G-080·G-081)은 모두 0.95 로 REVISE 됐다. 세 번의 실행을 합치면 이 규칙은 **recall 2/2, precision 2/7** — 모델은 조건 생략을 잘 잡지만 정상 소재에도 자주 붙인다. 심각도는 fix 로 두고 τ=0.90 이 과잉 적용을 사람 검토로 돌린다.
- 결정론 GRND-NUM-01 의 '오탐' 6건은 라벨 누락이었다(v1.1 에서 보정, fp 6→0). GRND-CLAIM-01 의 모델 오탐 2건은 FM-23 이 없앴다(fp 2→0).
- 레드팀 3차: 돌파 0, 사람 검토 0, REVISE 2(`implicature`). 공격자가 위반 표현을 암시로만 남긴 소재에 TA-OMISSION-01·TA-FEAR-01 로 수정 요청이 났다. 수확돼 회귀셋은 5건.

### 레드팀

| 모드 | 공격자 | 공격 수 | 돌파(APPROVE) | 사람 검토 | 비용 |
|---|---|---|---|---|---|
| demo | 결정론 변환기 | 32 | 0 | 0 | $0 |
| partial 1차 (run 38928048713) | gpt-4o | 32 | 0 | 2 | $0.47 |
| partial 2차 (run 38930364792, 정규화 수정 후) | gpt-4o | 32 | 0 | 0 | $0.49 |
| partial 3차 (run 38932009287) | gpt-4o | 32 | 0 | 0 | $0.48 |

partial 의 사람 검토 2건은 `zero_width` 전략이었다. 공격자는 제로폭 문자 대신 **NUL(`\x00`)·수직 탭·폼 피드** 를 글자 사이에 끼웠다. 정규화는 제로폭 집합만 제거하고 있었기 때문에 '원금\x00보장' 이 어휘 규칙을 통과했고, 심사 모델은 신뢰도 0.6 으로 REVISE 만 냈다. 결과는 사람 검토(안전)였지만 규칙이 잡지 못한 **근접 사례** 다.
조치: `normalize.is_invisible()` 이 유니코드 범주 Cc·Cf·Co·Cn·Cs·Mn·Me 와 한글 채움 문자·점자 공백·특수 공백을 모두 걷어낸다. 두 변형은 `adversarial.jsonl` 에 수확됐고(`harvest()` 는 이제 REJECT 가 아닌 모든 결과를 수확한다), CI 는 이 셋에서 위험 승인 0 을 요구한다. 수정 후 결정론 계층은 두 변형을 block 으로 잡는다 (`tests/test_lexical.py::test_live_redteam_nul_separator_regression`).
2차 실행에서는 32개 공격 모두 REJECT 또는 REVISE 였고 사람 검토는 0 이었다. REVISE 1건(`bury`)은 공격자가 최상급·비교 표현을 아예 빼 버려 남은 위반이 긴급성뿐이었던 경우라, 더 약한 소재에 더 약한 판정이 난 것이다. 이것도 수확돼 회귀셋은 3건이 됐다.

### 실제 트레이스

`traces/sample_partial_*.json` 은 같은 다섯 시나리오를 gpt-4o 로 돌린 기록이다(2차 실행본). 시나리오당 9~11회 호출, $0.09~0.11, 28~35초. '정상 요청' 시나리오에서 3개 변형 중 1개가 환각 인용으로 사람 검토에 갔고(1차는 2개), '악의적 요청' 시나리오에서는 같은 모델의 두 번째 의견이 첫 번째와 달라(REVISE vs APPROVE) 사람 검토로 갔다 — 키가 하나라 독립적인 교차 검증은 아니지만 같은 모델의 샘플 불일치도 불확실성 신호로 쓴다. 관측 탭에서 스팬을 열어 보면 어느 인용이 원문에 없었는지 보인다.

## 품질 판정자 (`evals/judge.py`)

소재 쌍대 비교는 순서를 바꿔 두 번 묻고, 결론이 뒤집히면 무승부로 처리한 뒤 위치 뒤집기율을 보고한다 (LLM-as-judge 의 위치 편향).

## 한계

- 라벨 저자 = 규칙 저자. 독립 라벨러·실제 반려 데이터가 없다.
- 표본이 작다 (53). 한 건이 수 %p 를 움직인다.
- demo 수치는 대역이 낸 것이라 모델 성능이 아니다. partial 수치는 OpenAI 한 계열만의 결과라 교차 검증의 독립성이 없다(같은 모델이 두 번 봤다). Anthropic 키를 추가하면 하이브리드 LIVE 로 다시 잴 수 있다.
- 프롬프트를 고친 뒤 같은 골든셋으로 재측정한 수치는 holdout 이 아니다. 첫 측정(run 38928048713) 수치를 그대로 남긴다.
- 이미지·영상 소재, 랜딩 페이지 실제 fetch 는 범위 밖이다 (텍스트만).
