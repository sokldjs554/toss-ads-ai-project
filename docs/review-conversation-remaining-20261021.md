# 남은 대화 3건의 확인·보완 경로 — 2026-10-21

## 결론과 범위

고정된 20개 대화의 점수는 **17/20으로 유지**한다. `h26-d04`의 성인 하한을 추측해서 채우거나 `h26-d05`, `h26-d12`의 예산 경고를 지워 점수를 올리지 않았다. 대신 d04에 명시적인 후속 답변을 한 번 받으면 원래 상한 34세를 보존하여 설정·모든 미리보기 세트·광고 작업 입력까지 전달할 수 있게 했다. 다른 두 사례는 원래부터 경고를 표시하며 진행할 수 있었다.

이 기록의 수정 후 실행은 **규칙·대역 및 통제된 가짜 제공자 검사**다. 실제 제공자 호출, 실제 광고 집행, 새 독립 평가를 했다는 뜻이 아니다. 실제 호출의 과거 3차 결과는 [원본 보고서](../evals/reports/live_features/features-20261020-run3.json)에 그대로 남는다.

## 원인 조사

| 사례 | 저장된 결과와 계약 | 확인한 문제 |
|---|---|---|
| `h26-d04` | “34세 이하”는 정확히 읽었지만 하한이 없다. 기존 계약은 `MINOR_TARGET`으로 진행을 막는다. 고정 라벨은 즉시 ready·문제 없음으로 되어 있다. | 차단 자체는 필요한 확인이다. 기존 질문은 실제 미성년 타겟과 상한만 말한 경우를 구별하지 않았다. 제시한 `20대`, `30대`, `만 19세 이상` 답은 상한을 보존하는 보완 답이 아니었다. `만 19세 이상`을 입력하면 충돌이 생겼다. |
| `h26-d05` | 월 52만원, ready, 미리보기 1세트. `BUDGET_LOW`는 warn이며 예산을 다시 묻지 않는다. | 라벨의 빈 문제 목록과 기존 계약이 다르다. 추출·준비 상태·진행에는 결함이 없다. |
| `h26-d12` | 월 48만원, ready, 미리보기 1세트. 같은 비차단 경고가 표시된다. | d05와 같은 라벨·계약 차이다. |

60만원은 세트를 두 개 이상으로 나누기 위한 **이 프로젝트의 가정**이고 실제 토스 Ads 최소 예산 규칙이 아니다. 기존 문구·경고 등급·한 세트 구성·ready 계약을 보존했다.

추가로, d04에 전체 범위 `만 19~34세`를 명시해도 기존 대역 플래너는 첫 세트를 `만 19세 이상`, 나머지는 연령이 없는 타겟으로 만들었다. `conform_plan()`은 목표·예산·세트 수·입찰만 맞추고 확인된 연령 제한을 적용하지 않았다. 즉, 설정이 안전해진 뒤에도 미리보기에서 상한이 사라지는 실제 결함이 있었다.

## 변경

`agents/conversation.py`에서 상한만 있는 경우에는 최소 연령이 확인되지 않았다고 설명하고, 상한을 유지한 질문과 `타겟을 만 19~34세로 바꿔 주세요` 같은 전체 범위 답변 버튼을 제공한다. 그대로 보낸 답은 사용자 발화로 기록된다. 직전 질문이 이 최소 연령을 물었을 때만 하나의 호환되는 하한 답(`만 19세 이상`, `만 23세 이상`, `성인`)을 기존 상한과 합친다. 이전 상한 구절과 이번 하한 구절을 각각 원문 근거로 보존한다.

`네`, 모호한 답, 미성년 하한, 기존 상한보다 큰 하한, 부정·선택 관계·별도 미성년 집단은 확인을 완료하지 못한다. 모델이 원문에 없는 19세 하한을 제안해도 기존 근거 검증에서 버린다. 명시적인 전체 타겟 변경은 기존 교체 경로를 따른다.

미리보기의 모든 세트는 사용자가 확인한 숫자 연령 제한과 교집합을 취한다. 더 좁은 연령 집단과 연령 이외의 세부 내용은 보존하며, 연령이 없는 세트에도 확인된 제한을 적는다. 같은 조건으로 이어진 하한·상한만 하나의 범위로 읽는다. 확인 범위와 전혀 겹치지 않거나 별도 미성년 집단을 포함한 제안은 다른 집단으로 덮어쓰지 않고 미리보기 생성을 멈춘다. 이때 `FM-02`와 `PLAN_UNAVAILABLE`을 남기며, 사용자가 확인한 설정 자체는 광고 작업 화면으로 전달할 수 있다.

모델 출력 스키마·동결 데이터·예산 임계값·원래 점수 계산식은 바꾸지 않았다. 새 UI 구현 없이 기존 질문 버튼·광고 작업 채우기 흐름을 사용한다.

## 남은 한계

자유로운 한국어 연령 표현 전체를 검증한 것은 아니다. 하한만 보완하는 문맥 처리는 바로 앞의 구체적 질문과 지원하는 단일 연령 구절로 제한된다. 복잡하거나 충돌하는 답은 전체 범위를 다시 명시해야 한다. 미리보기의 연령 검증도 기존 규칙 추출기가 읽는 표현에 한정되며, 타겟 규모·실제 제공자 이해력·심사 승인·실제 집행 가능성은 보장하지 않는다. 충돌하는 모델 집단 때문에 미리보기가 없을 때는 그 실패를 표시하고, 확인한 설정의 전달과 구분한다.
