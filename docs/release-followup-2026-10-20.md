# 2026-10-20 한계 보완·후속 검증 기록

## 결과와 읽는 순서

대화 해석의 기존 예상 실패 6개를 수정했고, 검수 대기열에 브라우저 자동 저장·복원을 추가했다. 성과 리포트는 기준값과 추세의 추정 오차를 반영하고, 원인을 단정하는 대신 근거와 확인 방법을 제시하도록 바꿨다. 별도 AI 작성자가 만든 새 입력에서 드러난 실패도 기록한 뒤 일반 로직을 수정했다.

**수정하며 본 사례의 성적과 처음 보는 입력의 성적은 다르다.** 기존 대화 회귀판은 **66/66**이지만 새 대화 20개의 첫 결과는 **14/20**이었다. 일반 파서 문제 3개를 수정한 뒤 같은 대화를 다시 검사한 결과는 **17/20**이다. 새 성과 시나리오 80개의 첫 실행에서는 찾을 대상으로 표시한 변화 **35개 중 18개**, 수정 후 같은 자료에서는 **33개**를 찾았다. 처음 실행한 데이터·라벨·결과·동결 지문은 보존하며, 수정 후 같은 입력의 결과를 새로운 독립 평가로 소개하지 않는다.

이 문서는 [앞선 작업 재개·검증 기록](release-2026-10-20.md)의 후속이다. 앞선 기록의 **3,689개 통과·예상 실패 6개**, 실제 모델을 호출하지 않았다는 설명, 당시 세션 메모리 대기열은 그 시점의 사실이다. 과거 문서를 고쳐 오늘의 구현처럼 보이게 만들지 않았다. 현재 검사 기준 버전은 **2026.10.5**이며, 이전 GPT-4o 평가의 검사 기준과 실행일은 그대로 남긴다.

## 1. 대화: 실패 수정과 평가 이력

| 구분 | 결과 | 의미 |
|---|---:|---|
| 최초 저장한 기존 대화 | 개발 40/40 · 최종 확인 분할 20/26 | 알려진 실패 6개가 있던 원본 기록 |
| 기존 원본을 수정 뒤 재실행 | 39/40 · 26/26 | 지시문 뒤 내용을 더 엄격하게 격리하면서 원본 `DLG-035`의 기대와 달라짐 |
| 계약을 명시한 회귀판 v2 | 40/40 · 26/26 | 이미 본 66개 대화에서 수정된 동작을 확인 |
| 별도 AI 작성자의 새 대화 20개 첫 실행 | 14/20 | 코드·데이터 동결 뒤 처음 실행한 값 |
| 일반 파서 문제 3개 수정 후 같은 20개 재검사 | 17/20 | 이미 본 입력의 회귀 검사. 원래 라벨을 바꾸지 않음 |

기존 예상 실패는 바꿔 쓴 한국어·영어 지시문, 이모지 표시 문자, 카페 업종, ‘40대 이상’, 여러 낱말의 말투 설명이었다. 실패를 실제로 재현한 뒤 수정했고 `tests/test_conv_known_gaps.py`의 예상 실패 표시를 제거했다. 지시문을 발견하면 같은 턴의 뒤쪽 내용은 격리하며, 다음 정상 턴에서는 다시 설정을 받을 수 있다. 이 계약을 테스트 ID별 예외로 구현하지 않았다. [상세 대화 검토](review-conversation-20261020.md).

새 20개에서 확인한 일반 파서 문제는 ‘건강 관리 서비스’의 업종 읽기, ‘보험이 아니라 적금으로 바꿔’ 같은 명시적인 업종 정정, 공격 다음 정상 턴의 명시적인 목표 변경이었다. 수정 후 정답에 값이 명시된 **64/64개 항목**은 맞았고, 이미 받은 정보를 다시 물은 결과는 **0/76**, 꼭 물어야 할 정보를 놓친 결과는 **0/6**이었다. 전체 대화 통과는 여전히 **17/20**이다. [세 문제의 재현·일반 수정·회귀 검사](review-dialog-holdout-followup-20261020.md).

나머지 3개는 다음과 같이 해석한다.

| 사례 | 실제 결과와 원래 기대의 차이 | 처리 |
|---|---|---|
| 투자 광고, ‘34세 이하’ | 성인만이라는 하한이 없어서 `MINOR_TARGET`으로 진행을 막음. 원래 기대는 준비 완료 | 미성년자 포함 가능성을 임의로 지우지 않음 |
| 월 52만원 | 값·준비 상태는 맞지만 `BUDGET_LOW`가 추가됨 | 원래 기대에서 빠진 예산 경고를 삭제하지 않음 |
| 월 48만원 | 값·준비 상태는 맞지만 `BUDGET_LOW`가 추가됨 | 원래 기대에서 빠진 예산 경고를 삭제하지 않음 |

월 60만원 기준은 이 프로젝트의 공개된 내부 가정이다. 실제 토스애즈 기준으로 검증한 값이 아니다. 위 세 라벨을 사후에 고치거나 사례를 제외해 20/20으로 보고하지 않는다.

금지 값 검사의 분모도 분리했다. 새 데이터의 공격 대화는 **4개**이고 공격 내용이 설정값에 섞인 결과는 **0/4**다. 원본 집계의 **0/7**에는 일반 수정 사례 3개가 함께 들어갔다. 첫 보고서의 잘못된 일반 메타데이터는 원본에 남겨 두고, 현재 평가기는 데이터별 작성 경위와 재실행 여부를 표시한다.

## 2. 성과 리포트: 과거의 잘못된 알림과 새 입력의 놓친 변화

선행 수정에서는 정상 변동을 여러 날짜에 걸쳐 더할 때 기준값·추세의 추정 오차가 빠져 신호를 과장하는 문제를 고쳤다. 기기별 클릭 배분 변화도 직접 확인하고, 근거 일치 점수가 높더라도 원인을 단정하지 않도록 보고서 검증과 화면 표현을 맞췄다. 기존 정상 분할에서 잘못된 알림은 **2/4에서 0/4**로 줄었고, 같은 분할의 변화 탐지는 **15/15**였다. 이는 이미 본 53개 시나리오를 재실행한 결과다. [선행 수정 근거](review-insights-followup-20261020.md).

그 엔진을 동결한 뒤 별도 AI 작성자가 만든 시나리오는 **80개**다. 정상 40개, 원인이 명확한 사건 32개, 불확실한 사례 8개를 포함한다. 첫 결과에서 실패를 확인한 뒤 일반 로직을 수정했으며, 아래 두 열은 같은 데이터의 첫 실행과 재검사다.

| 지표 | 첫 실행 결과 | 수정 후 같은 자료 재검사 |
|---|---:|---:|
| 찾을 대상으로 표시한 변화를 찾음 | 18/35 | 33/35 |
| 찾은 구간 중 사건과 겹침 | 19/19 | 34/34 |
| 정상 사례에 잘못된 알림 | 0/40 | 0/40 |
| 명확한 사건의 원인 1순위 일치 | 18/32 | 29/32 |
| 명확한 사건의 원인이 상위 3개에 포함 | 18/32 | 29/32 |
| 허용된 액션을 포함한 시나리오 | 66/80 | 76/80 |
| 해서는 안 되는 액션 제안 | 0 | 0 |
| 근거 없는 숫자 | 0 | 0 |
| 원본 보고서 점검 문제 | 1 | 0 |
| 인위적으로 바꾼 문장의 문제를 차단 | 881/881 | 913/913 |
| 정상 문장을 잘못 버린 수 | 11 | 0 |

첫 실행은 필요한 문제를 충분히 찾지 못했다. 보고서 방어 수치나 정상 사례 0/40만 앞세워 모두 해결됐다고 해석하지 않는다. 80개 자료는 같은 합성 생성기를 사용했고, 별도 AI 작성자는 독립적인 사람 라벨러가 아니다. [첫 결과·개별 사례·동결 기록](holdout-followup-20261020.md).

후속 수정은 비교할 최근 14일을 그대로 두고, 그 앞의 기준 기간에 변화가 이미 섞인 경우도 검사하도록 했다. 최소 두 주의 요일 주기를 포함하는 여러 기준 기간을 살피고, 비교 횟수·추세 추정의 불확실성을 함께 반영한다. 사건 시작을 직접 관측하지 못했으면 갑작스러운 변화라고 단정하지 않는다. 요일 보정 결과와 원자료의 방향이 다를 때 보고서 문장이 잘못된 방향을 말하던 문제도 수정했다. 사건 ID·시드·정답별 예외나 임계값을 낮추는 방식은 쓰지 않았다.

변화 2개는 여전히 놓쳤다. `h26-p059`는 한 광고세트의 전환 감소이고, `h26-p077`은 기기 구분을 없앤 약한 구성 변화다. `h26-p056`과 `h26-p064`는 변화는 찾았지만 원인을 정하지 못했다. 특히 `h26-p064`는 추세를 반영한 기대값에 비해 클릭당 비용 +9.0%, 노출 -5.1%로, 기존 입찰 경쟁 조건(+12%·-10%)에 못 미쳤다. 이전 요일 평균은 변화를 더 크게 보이게 했다. 계산을 바로잡은 뒤 원인 일치는 30/32에서 29/32, 허용 액션 일치는 77/80에서 76/80으로 낮아졌으며 그 차이를 그대로 공개한다. 이 실패를 숨기거나 원래 사건 시작 시점·강도·기대값을 바꾸어 점수를 올리지 않았다. 문장 변형 시험의 분모는 각 실행에서 생성된 보고서에 따라 달라지므로 881개와 913개를 같은 문장 집합으로 해석하지 않는다.

최종 문장·수치 수정에서는 추세가 있는 기준 기간을 과거 수준 평균과 비교하던 문제도 고쳤다. 직접 작성한 상승 추세+하락 사건은 +45.5%라는 반대 방향 설명에서 -24.1%로, 하락 추세+상승 사건은 -31.2%에서 +40.1%로 바뀌었다. 요약 카드·사건 근거·보고서는 같은 추세 예측값을 사용한다. 실제 시작일을 관측하지 못한 경우 관측 구간 첫날을 실제 시작일로 말하는 문장을 거절하고, 근거 ID만 붙여 기준 기간과 시작일 한계 설명을 생략할 수 없도록 했다. 템플릿 제목으로 대체할 때에는 수치 근거의 인용도 유지한다. `tests/test_insights_trend_report.py`와 `tests/test_insights_reference_guard.py`가 이 경계를 확인한다.

최종 엔진 지문은 `3185135f39763f7f`, 보고서 프롬프트 버전은 `2026.10.20.4`이다. 새 두 보고서는 모두 `holdout_role: regression`으로 표시한다. 기존 53개에서는 변화 **31/31·15/15**, 정상 사례의 잘못된 알림 **0/8·0/4**를 유지했다. 실제 광고 계정의 변화, 원인의 정확성, 제안 뒤 성과 개선을 측정한 것은 아니다.

## 3. 검수 대기열: 새 세션과 서버 재시작 뒤 복원

대기열·라벨·설정은 **같은 사이트 주소의 같은 브라우저 프로필**의 IndexedDB에 자동 저장된다. 초기 저장본을 검증해 복원하기 전에는 편집을 열지 않으며, 쓰기 요청만 성공했다고 저장됐다고 표시하지 않는다. 트랜잭션 완료를 확인한 뒤 성공 안내를 보여 준다.

| 확인한 상황 | 결과 |
|---|---|
| 실제 Streamlit에서 광고 추가·라벨 제출 후 새로고침 | 동일한 라벨 자동 복원, 저장 JSONL 일치 |
| Streamlit 서버 프로세스 종료·재시작 | 브라우저 저장본에서 동일한 라벨 자동 복원 |
| 실제 stlite 1.11.0·Chromium 134에서 페이지 새로고침 | 같은 광고 자동 복원, 페이지 오류 없음 |
| 같은 이전 버전에서 8회 동시 저장 | 1회 저장·7회 충돌. 새 저장본을 조용히 덮어쓰지 않음 |
| 저장 공간 부족·권한 거부·손상 레코드 | 성공으로 표시하지 않고 다음 편집을 막음. 백업·복구 경로 제공 |
| 전체 JSONL 백업 | 20만 자를 넘는 큐도 전체 파일로 내려받음 |

실제 stlite 검증에서 저장 컴포넌트의 상대 JS 경로가 404를 내는 문제를 발견했다. 배포 번들에 동일한 저장 JS를 포함하도록 수정한 뒤 복원을 다시 확인했다. [구현과 실패 후 통과 기록](review-persistence-20261020.md), [stlite 결과](evidence/persistence-2026-10-20/stlite-result.json).

이 저장은 개인별 작업 보존이다. 팀 공동 데이터베이스, 계정 인증, 접근 권한, 알림 전송, 여러 기기의 실시간 협업은 구현하지 않았다. Render와 GitHub Pages의 저장본은 사이트 주소가 달라 별개다. 사이트 데이터·브라우저 프로필을 지우거나 기기를 잃으면 저장본을 잃을 수 있으므로 중요한 작업은 전체 JSONL 백업으로 보관한다.

## 4. 실제 모델 호출과 보존한 기록

이 문서의 대화·성과 수치는 규칙, 대역 제공자, 합성 데이터로 검사한 값이다. 기존 실제 GPT-4o 광고 심사 평가와 방식 비교는 과거 실행일·검사 기준·프롬프트 버전 그대로 보존했다. 그 값을 현재 검사 기준 2026.10.5의 재평가나 새 기능의 실제 모델 결과로 바꾸어 표시하지 않는다.

현재 문서에 인용한 결과는 대화 모델의 자연어 이해력, 실제 비전 모델의 글자 읽기 품질, 모델이 쓴 성과 보고서의 실제 응답 품질을 입증하지 않는다. 실제 API 실행은 제공자·모델·호출 수·비용·실패 여부·입력 출처를 가진 별도 결과 파일로 확인해야 한다. 예시 실행이나 저장된 결과 열람 자체는 유료 호출을 발생시키지 않는다.

## 5. 재현과 검증 근거

현재 확인할 자료는 다음과 같다. 각 검토 문서의 범위 검사를 저장소 전체 검사나 실제 모델 평가로 확대하지 않는다.

| 영역 | 검증 근거 |
|---|---|
| 대화·지시문 경계 | [대화 검토](review-conversation-20261020.md)의 범위 검사와 회귀 데이터, 현재 `tests/test_conv_*` |
| 성과 계산·가설·문장 검증 | [성과 후속 검토](review-insights-followup-20261020.md)와 별도 첫 실행 보고서 |
| 저장·복원·충돌·실패 | [저장 검토](review-persistence-20261020.md)의 Python·AppTest·실제 브라우저 증거 |
| 새 입력 작성과 결과 보존 | [첫 실행 기록](holdout-followup-20261020.md) 및 데이터별 provenance 파일 |
| 현재 표와 저장 결과 일치 | `python scripts/gen_feature_docs.py --check` |

통합 검사의 완료 시점도 구분한다. 최종 추세·문장 보완 전 전체 검사는 **3,878개 통과**였고, 그 수치를 최종 소스 전체 검사의 결과로 바꾸어 표시하지 않는다. 최종 보완의 표적 검사 53개와 관련 범위 검사 185개는 통과했다. 로컬 Streamlit의 데스크톱·모바일 전체 브라우저 흐름은 위젯 준비 완료를 기다리도록 검사 도구를 고친 뒤 **122/122**를 통과했다. 첫 실행에서 실패한 검사 1개와 당시 화면은 `docs/screenshots/e2e_first_attempt.json` 및 `_fail_mobile*.png`로 보존한다. 이 122개 검사는 공개 stlite 사이트의 전체 흐름 검증이 아니다. stlite 저장·복원 검증은 3절의 별도 기록을 따른다.

재실행은 보존한 첫 보고서를 덮어쓰지 않는 경로에 저장한다.

```bash
python -m pytest -o addopts='' -q -ra
python -m evals.dialogs --split all --gate --out /tmp/dialogs-regression.json
python -m evals.dialogs --dataset evals/datasets/dialogs_holdout_20261020.jsonl --split all --out /tmp/dialogs-holdout-replay.json
python -m evals.insights_eval --split all --gate --regression --out /tmp/insights-regression.json
python -m evals.insights_eval --dataset evals/datasets/perf_holdout_20261020.jsonl --split holdout --regression --out /tmp/insights-holdout-replay.json
python scripts/gen_feature_docs.py --check
```

실제 브라우저 저장 검사는 Playwright·Chromium을 사용한다. stlite 검사는 공개 런타임을 읽지만 유료 모델 API를 호출하지 않는다. 첫 보고서와 과거 동결 지문을 유지하는 것은 점수의 약점을 숨기지 않고 다음 수정의 효과를 같은 입력에서 비교하기 위한 조건이다.
