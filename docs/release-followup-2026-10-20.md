# 2026-10-20~21 한계 보완·후속 검증 기록

## 결과와 읽는 순서

대화 해석의 기존 예상 실패 6개를 수정했고, 검수 대기열에 브라우저 자동 저장·복원을 추가했다. 성과 리포트는 기준값과 추세의 추정 오차를 반영하고, 원인을 단정하는 대신 근거와 확인 방법을 제시하도록 바꿨다. 별도 AI 작성자가 만든 새 입력에서 드러난 실패도 기록한 뒤 일반 로직을 수정했다.

**수정하며 본 사례의 성적과 처음 보는 입력의 성적은 다르다.** 기존 대화 회귀판은 **66/66**이지만 새 대화 20개의 첫 결과는 **14/20**이었다. 일반 파서 문제 3개를 수정한 뒤 같은 대화를 다시 검사한 결과는 **17/20**이다. 새 성과 시나리오 80개의 첫 실행에서는 찾을 대상으로 표시한 변화 **35개 중 18개**, 수정 후 같은 자료에서는 **33개**를 찾았다. 처음 실행한 데이터·라벨·결과·동결 지문은 보존하며, 수정 후 같은 입력의 결과를 새로운 독립 평가로 소개하지 않는다.

이 문서는 [앞선 작업 재개·검증 기록](release-2026-10-20.md)의 후속이다. 앞선 기록의 **3,689개 통과·예상 실패 6개**, 실제 모델을 호출하지 않았다는 설명, 당시 세션 메모리 대기열은 그 시점의 사실이다. 과거 문서를 고쳐 오늘의 구현처럼 보이게 만들지 않았다. 현재 검사 기준 버전은 **2026.10.5**이며, 이전 GPT-4o 평가의 검사 기준과 실행일은 그대로 남긴다.

**2026-10-21 UTC 세 번째 실제 실행까지 완료했다.** 같은 76개 입력을 세 번 검사한 결과는 대화 **12/20→17/20→17/20**, 성과 문장 최종 검사 **10/12→12/12→12/12**, 문구 선호 **22/28→21/28→21/28**이다. 낮아진 선호 결과와 남은 정책·라벨 차이도 숨기지 않는다. 세 번의 실제 API 응답은 **444/444**, 사용량 기준 비용 합계는 **$0.96774375**다. 자세한 소스·호출 장부·해석은 5절, CI·브라우저 증거는 6절에 있다.

## 2. 성과 리포트: 과거의 잘못된 알림과 새 입력의 놓친 변화

선행 수정에서는 정상 변동을 여러 날짜에 걸쳐 더할 때 기준값·추세의 추정 오차가 빠져 신호를 과장하는 문제를 고쳤다. 기기별 클릭 배분 변화도 직접 확인하고, 근거 일치 점수가 높더라도 원인을 단정하지 않도록 보고서 검증과 화면 표현을 맞췄다. 기존 정상 분할에서 잘못된 알림은 **2/4에서 0/4**로 줄었고, 같은 분할의 변화 탐지는 **15/15**였다. 이는 이미 본 53개 시나리오를 재실행한 결과다. [선행 수정 근거](review-insights-followup-20261020.md).

그 엔진을 동결한 뒤 별도 AI 작성자가 만든 시나리오는 **80개**다. 정상 40개, 원인이 명확한 사건 32개, 불확실한 사례 8개를 포함한다. 첫 결과에서 실패를 확인한 뒤 일반 로직을 수정했으며, 아래 두 열은 같은 데이터의 첫 실행과 재검사다.

첫 실행은 필요한 문제를 충분히 찾지 못했다. 보고서 방어 수치나 정상 사례 0/40만 앞세워 모두 해결됐다고 해석하지 않는다. 80개 자료는 같은 합성 생성기를 사용했고, 별도 AI 작성자는 독립적인 사람 라벨러가 아니다. [첫 결과·개별 사례·동결 기록](holdout-followup-20261020.md).

후속 수정은 비교할 최근 14일을 그대로 두고, 그 앞의 기준 기간에 변화가 이미 섞인 경우도 검사하도록 했다. 최소 두 주의 요일 주기를 포함하는 여러 기준 기간을 살피고, 비교 횟수·추세 추정의 불확실성을 함께 반영한다. 사건 시작을 직접 관측하지 못했으면 갑작스러운 변화라고 단정하지 않는다. 요일 보정 결과와 원자료의 방향이 다를 때 보고서 문장이 잘못된 방향을 말하던 문제도 수정했다. 사건 ID·시드·정답별 예외나 임계값을 낮추는 방식은 쓰지 않았다.

변화 2개는 여전히 놓쳤다. `h26-p059`는 한 광고세트의 전환 감소이고, `h26-p077`은 기기 구분을 없앤 약한 구성 변화다. `h26-p056`과 `h26-p064`는 변화는 찾았지만 원인을 정하지 못했다. 특히 `h26-p064`는 추세를 반영한 기대값에 비해 클릭당 비용 +9.0%, 노출 -5.1%로, 기존 입찰 경쟁 조건(+12%·-10%)에 못 미쳤다. 이전 요일 평균은 변화를 더 크게 보이게 했다. 계산을 바로잡은 뒤 원인 일치는 30/32에서 29/32, 허용 액션 일치는 77/80에서 76/80으로 낮아졌으며 그 차이를 그대로 공개한다. 이 실패를 숨기거나 원래 사건 시작 시점·강도·기대값을 바꾸어 점수를 올리지 않았다. 문장 변형 시험의 분모는 각 실행에서 생성된 보고서에 따라 달라지므로 881개와 913개를 같은 문장 집합으로 해석하지 않는다.

최종 문장·수치 수정에서는 추세가 있는 기준 기간을 과거 수준 평균과 비교하던 문제도 고쳤다. 직접 작성한 상승 추세+하락 사건은 +45.5%라는 반대 방향 설명에서 -24.1%로, 하락 추세+상승 사건은 -31.2%에서 +40.1%로 바뀌었다. 요약 카드·사건 근거·보고서는 같은 추세 예측값을 사용한다. 실제 시작일을 관측하지 못한 경우 관측 구간 첫날을 실제 시작일로 말하는 문장을 거절하고, 근거 ID만 붙여 기준 기간과 시작일 한계 설명을 생략할 수 없도록 했다. 템플릿 제목으로 대체할 때에는 수치 근거의 인용도 유지한다. `tests/test_insights_trend_report.py`와 `tests/test_insights_reference_guard.py`가 이 경계를 확인한다.

첫 실제 호출 전에 저장한 이 회귀 결과의 엔진 지문은 `3185135f39763f7f`, 보고서 프롬프트 버전은 `2026.10.20.4`다. 두 보고서는 모두 `holdout_role: regression`으로 표시한다. 기존 53개에서는 변화 **31/31·15/15**, 정상 사례의 잘못된 알림 **0/8·0/4**를 유지했다. 이후 실제 호출에서 발견한 문장 검증 문제의 수정은 별도 이력이며 이 버전을 현재 소스 전체의 최종 상태로 주장하지 않는다. 실제 광고 계정의 변화, 원인의 정확성, 제안 뒤 성과 개선을 측정한 것은 아니다.

## 3. 검수 대기열: 새 세션과 서버 재시작 뒤 복원

대기열·라벨·설정은 **같은 사이트 주소의 같은 브라우저 프로필**의 IndexedDB에 자동 저장된다. 초기 저장본을 검증해 복원하기 전에는 편집을 열지 않으며, 쓰기 요청만 성공했다고 저장됐다고 표시하지 않는다. 트랜잭션 완료를 확인한 뒤 성공 안내를 보여 준다.

| 확인한 상황 | 결과 |
|---|---|
| 실제 Streamlit에서 광고 추가·라벨 제출 후 새로고침 | 동일한 라벨 자동 복원, 저장 JSONL 일치 |
| Streamlit 서버 프로세스 종료·재시작 | 브라우저 저장본에서 동일한 라벨 자동 복원 |
| 실제 stlite 1.11.0·Chromium 134에서 페이지 새로고침 | 같은 광고 자동 복원, 페이지 오류 없음 |
| 같은 이전 버전에서 8회 동시 저장 | 1회 저장·7회 충돌. 새 저장본을 조용히 덮어쓰지 않음 |
| 저장 공간 부족·권한 거부·손상 레코드 | 성공으로 표시하지 않고 다음 편집을 막음. 백업·복구 경로 제공 |
| 전체 JSONL 백업 | 20만 자를 넘는 큐도 전체 파일로 내려받음 |

실제 stlite 검증에서 저장 컴포넌트의 상대 JS 경로가 404를 내는 문제를 발견했다. 배포 번들에 동일한 저장 JS를 포함하도록 수정한 뒤 복원을 다시 확인했다. [구현과 실패 후 통과 기록](review-persistence-20261020.md), [stlite 결과](evidence/persistence-2026-10-20/stlite-result.json).

추가로 Chromium 141에서 stlite 1.11.0·1.12.0 각각 **12/12**의 저장·복원 검사를 완료했다. 두 버전에 같은 `d9633d6` 소스 묶음을 넣고 저장 완료·revision 증가·본 앱에서 담당자 배정·새로고침 후 같은 광고 복원을 확인했다. 각 버전의 프레임워크 진단 요청 실패 8건·콘솔 오류 24건은 그대로 기록했다. 실제 저장 경로가 별도로 동작하므로 이 로그를 저장 실패나 새 버전의 기능 회귀로 해석하지 않는다. [비교 조건·snapshot·원본 로그](evidence/final-2026-10-21/stlite-upgrade/storage-compatibility/README.md). 이전 호환성 검사의 selector 실패와 부분 확인 결과도 전체 통과로 바꾸지 않았다.

### 실제 호출 결과가 의미하는 범위

입력은 AI 작성 합성 자료와 기존 작성자의 선호 라벨이다. 대화·성과 자료는 실제 호출 전에 이미 규칙 수정에 사용했다. 12개 성과 사례의 선택, 배너 12장, 문구 28쌍의 두 순서, 가상 브리프 4개는 유료 호출 전에 계획 파일에 고정했고, 소스·입력별 해시는 보고서의 `manifest`에 있다. 실제 제공자를 연결한 경로를 검사한 결과이며 새로운 맹검 평가나 독립적인 사람 검증이 아니다.

이미지 12/12는 고정 글자 배너의 조건 검사다. 빈 이미지가 담당자 확인으로 가는 조건도 포함하므로 12장 모두의 글자를 정확히 읽었다는 뜻이 아니다. 일반 사진·로고·작은 글자 전체의 정확도를 뜻하지도 않는다. 문구 선호 일치는 클릭률·전환·광고주 만족의 검증이 아니다. 캠페인 구성·문구 생성·검사 4/4는 예산 합계, 광고안 2개의 검사, 코드상 금지 광고가 통과하지 않음, 단계 완료를 확인한 값이며 실제 캠페인을 집행한 결과가 아니다. 세 실행 모두 각 광고안 8개가 점검 통과였으므로 자동 수정·재시도 분기를 실제 호출로 검증한 결과도 아니다. URL 수집과 4절의 후속 URL 수정은 이 실제 API 평가 범위에 없다.

기존 GPT-4o 광고 심사 평가와 110건 방식 비교는 과거 실행일·검사 기준·프롬프트 버전 그대로 보존한다. 이번 GPT-5.4-mini 실행으로 그 비교 표나 5차 기준선을 다시 측정했다고 표시하지 않는다. 예시 실행과 저장된 결과 열람 자체는 유료 호출을 발생시키지 않는다.
