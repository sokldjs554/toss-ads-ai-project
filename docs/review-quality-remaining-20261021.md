## 2. 새 비교 계약

### 전송하는 입력

모델에는 상품 사실의 ID/문장과 두 광고의 `headline`, `body`, `cta`만 보낸다. 작성자 정답, 이유 코드, 사례 ID, 기존 규칙 점수, 원래 문구 위치, 변형 ID는 광고 데이터에 넣지 않는다. 사례 ID는 호출 장부의 라벨에만 사용된다.

정상 순서와 반대 순서를 각각 한 번씩 호출한다. 한 순서로 정렬해 불안정을 감추거나, 맞는 답이 나올 때까지 추가 호출하거나, 세 번째 응답으로 기존 실패를 바꾸는 동작은 없다. 두 응답은 서로의 답을 보지 않는다. 공유된 모델·제공자를 쓸 수 있으므로 서로 다른 판단 주체의 독립 검토라고 부르지는 않는다.

프롬프트는 네 관점으로 문구 전체를 읽게 한다.

| 기준 | 비교 내용 |
|---|---|
| information | 상품/혜택의 구체성과 정확한 이해. 사실에 없는 숫자는 구체성의 장점으로 삼지 않음 |
| conditions | 언급한 혜택의 비용·기간·자동결제·제한. 필수 조건과 선택적 부가 기능의 차이 |
| action | 버튼을 읽고 다음 행동을 알 수 있는지 |
| expression | 문장 이해, 중복, 군더더기, 과장, 말투 일관성이 전달에 미치는 영향 |

각 관점은 양쪽 원문 인용, 관련 사실 ID, 상대 선호, 차이의 중요도, 짧은 이유를 기록한다. 중요도는 `material/minor/none/unknown`의 순서 범주이며, 클릭 확률이나 품질의 숫자 점수가 아니다. 기준별 점수를 만들어 더하거나 기존 규칙 점수에 맞추지 않는다.

`material`은 이해나 다음 행동을 명확히 바꾸는 차이, `minor`는 작은 표현 선호다. 승자는 적어도 하나의 중요한 근거가 있을 때만 허용한다. 비슷한 문체·배치 차이는 무승부가 될 수 있으며 근거 부족은 판단 보류다. 한쪽에만 중요한 차이가 있다고 작성한 뒤 동시에 무승부라고 답하는 내부 모순도 검출한다. 중요도 자체의 의미 판단은 여전히 모델의 판단이며, 소프트웨어가 사람의 선호로 인증하지 않는다.

### 출처 검사

`audit_evidence`는 다음을 검사한다.

- 네 기준이 중복·누락 없이 존재한다.
- 양쪽 인용이 각각 지정한 광고의 지정한 필드에 문자 그대로 있다. 다른 광고의 인용을 옮기거나 빈 문자열로 검사를 우회할 수 없다. 빈 문자열은 실제로 빈 필드에만 허용한다.
- 행동 비교에는 양쪽 버튼의 인용이 있어야 한다.
- 참조한 사실 ID가 제공한 사실에 존재한다. 사실과 관련된 중요한 차이에는 사실 참조가 있어야 한다.
- 상대 선호와 중요도, 최종 선택과 결정 근거가 서로 일관된다.
- 사실이 없으면 조건 판단을 임의로 확정하지 않는다.
- 네 기준을 전부 모른다고 적은 뒤 무승부로 확정하면 `tie_without_comparison`으로 거절한다. 판단하지 못했다는 응답이 무승부 성공으로 바뀌지 않는다.

**문자열의 출처가 맞아도 인용이 그 이유를 의미적으로 뒷받침한다는 보장은 없다.** 모델이 중요한 조건을 놓치거나, 존재하는 인용을 잘못 해석하거나, 두 번 똑같이 잘못 판단할 수 있다. `evidence_valid`는 위의 출처/구조/내부 일관성 검사를 통과했다는 뜻이다.

### 합산과 보류

모든 선택은 원래 문구 `a/b`로 복원한 뒤 비교한다. 최종 값과 처리 상태를 분리한다.

| status | 최종 winner | 의미 |
|---|---|---|
| consensus | a / b / tie | 두 순서가 같은 결론이고 출처/계약 검사를 통과함 |
| order_disagreement | abstain | 두 순서의 최종 선택이 다름. 무승부 정답으로 세지 않음 |
| rubric_disagreement | abstain | 전체 선택은 같지만 적어도 하나의 중요한 기준에서 차이의 방향이나 중요도가 달라짐 |
| invalid_evidence | abstain | 출처/내부 일관성 검사 실패 |
| judge_abstained | abstain | 모델이 근거 부족을 명시함 |
| incomplete | abstain | 한쪽 응답 실패·누락·스키마 실패·예산 중단 |

`position_consistent`는 원래 문구 기준의 선택이 같은지, `dimension_consistent`는 중요한 기준의 판단이 같은지를 별도로 남긴다. 미측정인 경우 `None`이다. 두 순서의 원본 구조화 응답, 표시상 A/B 선택, 복원한 선택, 근거 검사 문제, 제공자·모델·수리 여부를 보관한다.

한쪽 호출이 실패해도 이미 받은 다른 응답은 남는다. 예외 메시지는 민감 정보가 섞일 수 있어 타입만 기록한다. 예산 중단은 `budget_stopped`로 호출자에게 전달한다. 호출자는 이 부분 결과를 저장한 뒤 전체 실측을 멈출 수 있다. 추가 호출의 실제 횟수·비용·제공자 전환은 기존 라우터/실측 장부가 관리한다.

새 검사는 기존 run1/2/3보다 조건이 많다. 따라서 새 실행의 “모든 검사 통과” 수를 과거의 단순 순서 일치+작성자 선호 일치 수와 같은 지표처럼 비교하면 안 된다. 기존 두 지표, 새 근거 검사, 기준별 일관성, 보류 사유를 따로 읽어야 한다.

### 실제 runner와 화면의 표시

기존 다섯 기능 `vision/conversation/insights/quality/pipeline`의 그룹과 분모는 그대로다. 품질 행의 기존 `checks`, `model_winner`, `orders`, 작성자 라벨은 과거와 비교 가능한 원시 지표로 보존했다. 별도로 `accepted_winner`, `aggregation_status`, `quality_checks`와 `quality_audit_summary`를 기록한다. 따라서 두 순서가 우연히 같은 승자를 내고 작성자 라벨도 맞았더라도 중요한 근거가 서로 모순되면 원시 지표만 일치하고 실제 선택은 `abstain`이다.

`ui/new_evals.py`는 새 보고서의 품질 결과를 **채택한 쌍 / 보류한 쌍 / 채택하고 작성자 라벨과 일치한 쌍 / 과거와 비교할 원시 일치 수**로 나눠 보여 준다. 기존 두 검사만 녹색인 행을 품질 통과라고 표시하지 않는다. 예산이 한 순서 뒤에 끝나면 받은 원문을 체크포인트에 남기고 전체 실행을 중단한다. 두 번째 호출이 없는 쌍에 완료나 일치 크레딧을 주지 않는다.

실제 수정 제안과 재검사 분기는 기존 5개 그룹과 별도의 보조평가로 추가했다. 원문 위반, 실제 모델의 수정안 생성, 같은 정책의 실제 모델 재검사가 모두 있어야 성공이다. 입력 동결과 장부 검증 방법은 `docs/review-rewrite-supplement-20261021.md`에 기록했다.

## 3. 저장 응답 재생과 검증

재생 결과는 `docs/evidence/quality-remaining-20261021/saved-response-replay.json`에 있다. 세 리포트 84쌍을 모두 읽었으며 원본 파일의 해시, 기존 선택, 재생 결과, 검사하지 못한 근거 상태를 기록했다.

- run1의 불일치 5쌍, run2의 6쌍, run3의 6쌍은 전부 `abstain`으로 보존된다.
- 각 실행의 H13 안정적인 `tie`도 그대로다.
- 원래 두 순서의 응답 배열을 변경하거나 삭제하지 않는다.
- 옛 응답에는 새 필드별 인용 계약이 없으므로 `evidence_basis=legacy_unchecked`, `evidence_valid=None`이다. 과거 자유 서술을 새 근거 검사에 통과한 것으로 꾸미지 않는다.
- 이 재생은 네트워크/모델 호출을 하지 않으며 새 모델 성능 측정이 아니다.

테스트는 먼저 없는 계약/누락된 검사에서 실패하는 것을 확인한 뒤 구현했다. 처음 새 비교 계약 17개 테스트가 실패했고, 중요한 근거의 순서 불일치·내부 모순·버튼 출처 3개도 해당 동작이 없을 때 실패했다. 사람이 실제로 읽는 `pairs.md`의 변경을 놓치는 검사와 네 기준 모두 미판정인데 무승부로 확정되는 검사도 각각 실패를 재현한 뒤 보완했다.

## 4. 별도 사람 검토를 위한 준비

실제 사람이 평가한 라벨은 만들지 않았다. 초대·메시지 발송도 하지 않았다. 준비된 자료는 **28쌍 전부에 대한 빈 검토 자료**다.

- 검토자에게 전달할 파일: `docs/human-review/quality-20261021/reviewer-packet.zip`
- ZIP 안: `pairs.md`, `cases.json`, `instructions.md`, 빈 `labels.csv`
- 운영자에게만 필요한 매핑: 같은 디렉터리의 `coordinator-manifest.json` — ZIP에 포함되지 않는다.

자료에는 기존 사례 ID·작성자 라벨·이유 코드·작성자 메모·규칙 점수·모델 답이 없다. 사례 순서와 좌우 위치를 바꾸고 불투명한 사례 ID를 부여했다. 두 광고와 상품 사실은 원문 그대로다. 평가자는 `left/right/tie/abstain`, 확신 `low/medium/high`, 직접 쓴 이유를 입력한다. CSV의 28개 평가 행은 모두 비어 있다.

새 검토자용으로 다른 순서의 자료를 만들려면 새 디렉터리와 ID를 사용한다. 기존 자료나 제출물을 덮어쓰는 내보내기는 거절한다.

```bash
.venv311/bin/python -m evals.quality_human_review export \
  --out /tmp/quality-review-new \
  --packet-id quality-review-new --split holdout
```

실제로 직접 평가한 사람이 제출한 다음에만 가져온다. 아래 reviewer ID는 실제 담당자가 정한 가명 ID로 대체한다. 세 확인 플래그는 실제 제출자에게 사람 직접 작성·독립 검토·기존 라벨 미열람을 확인했을 때만 사용한다.

```bash
.venv311/bin/python -m evals.quality_human_review import \
  --submission /path/to/completed-labels.csv \
  --packet docs/human-review/quality-20261021/reviewer/cases.json \
  --manifest docs/human-review/quality-20261021/coordinator-manifest.json \
  --reviewer-id REVIEWER_PSEUDONYM \
  --attest-human --attest-independent --attest-blinded \
  --out /path/to/new-human-submission.json
```

가져오기는 다음을 확인한다.

- 원본 데이터셋, 블라인드 JSON, 실제 읽는 Markdown/안내문의 해시와 원본 문구 매핑.
- 완전한 사례 집합, 중복/알 수 없는 ID/다른 packet ID 거부.
- 평가 값·확신 값의 허용 목록과 비어 있지 않은 이유. 미작성은 무승부나 사람 라벨로 채우지 않는다.
- 기존 파일 덮어쓰기 금지. 기존 AI 작성 라벨과 실측 리포트로 병합하지 않고 별도 JSON으로 보관.

결과의 출처는 `human_submission`이며 `identity_verified=false`, `independence_verified=false`다. 확인 플래그는 제출자의 진술을 기록한 것이다. 파일 해시는 변경 탐지에 쓰며 사람의 신원, 실제로 어떤 자료를 봤는지, 독립성을 증명하는 전자서명이 아니다. 테스트의 입력은 명시적인 통제된 테스트 자료이며 실제 제출물로 보관하지 않는다.

## 5. 아직 해결되지 않은 판단 한계

1. **인용 출처 검사로 의미 이해를 보증할 수 없다.** 서로 다른 문구를 두 번 일관되게 오해하면 합산으로 발견하지 못한다. 관련 사실 ID가 존재한다는 검사도 이유의 논리적 타당성을 인증하지 않는다.
2. **사람의 선호와 광고 성과 데이터가 없다.** H13 같은 문체의 중요도와 H27의 서로 다른 정보량 중 무엇이 더 유용한지는 독립 검토가 필요하다. 실제 성과 예측이나 선호 정답을 생성하지 않았다.
3. **보류는 성능 향상 점수가 아니다.** 보류가 늘면 잘못된 확정 선택을 줄일 수 있지만, 판단할 수 있는 쌍의 비율도 낮아진다. 최종 보고에는 전체 분모, 보류 수, 보류 사유, 확정한 쌍의 일치율을 함께 제시해야 한다.
4. **기존 holdout은 이번 원인 분석에서 읽었다.** 앞으로 같은 28쌍에 대한 실행은 회귀 측정이다. 새 프롬프트의 일반화를 입증하는 손대지 않은 holdout으로 취급하지 않는다. 독립 작성 사례와 독립 검토자를 별도로 확보해야 한다.
5. **블라인드 자료는 독립 라벨 그 자체가 아니다.** 최소 두 사람이 서로의 답이나 모델 답을 보지 않고 전체 사례를 평가하고, 각 사람의 원래 답과 이견을 보관한 뒤 일치도를 살펴야 한다. 한 사람의 의견이나 합의된 답만 남겨 이견을 지우면 안 된다. 아직 실제 제출은 0건이다.

신호·라벨·사례를 나쁜 결과에 맞춰 조정하지 않았으며, 실제 모델의 의미 판단이 좋아졌는지는 새 실측과 독립 검토가 남아 있다.
