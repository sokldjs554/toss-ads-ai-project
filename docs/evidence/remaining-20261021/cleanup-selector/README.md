# 공동 검수 QA의 계정 선택·정리 확인

공개 검수 QA 스크립트에서 **이미 선택된 첫 담당자**의 이름을 다시 입력하면 Streamlit 선택 목록이 열리지 않아 기다리던 문제가 있었다. 입력값이 사라지는 문제라는 가설은 실제 DOM 관측과 달랐다. `select_cleanup_account`가 `ArrowDown`으로 목록을 먼저 연 뒤 이름을 찾도록 한 줄을 수정했다.

[결과](result.json)는 Streamlit 1.66·로컬 Chromium·기존 테스트용 MemoryStore에서 합성 담당자 두 명으로 확인한 기록이다. 처음 선택된 활성 A, 다른 활성 B, 비활성 B 재선택을 포함해 **10개 확인을 통과**했다. 화면 입력값뿐 아니라 독립적으로 표시한 서버의 선택 계정·활성 상태도 대조했다.

[실행한 재현 코드](reproduce.py)는 QA 파일의 `area`와 `select_cleanup_account` 두 함수만 AST로 가져온다. 비밀값을 읽는 공개 QA의 main은 실행하지 않는다. 당시 실행 환경의 저장소·Python·Chromium 절대 경로가 고정된 증거 사본이므로 다른 환경에서 재현할 때 이 경로를 바꿔야 한다.

제품 동작, 실제 DB 계정, 외부 서비스에 대한 변경은 없다. 외부 DB 호출 0회·실제 사람 제출 0건이다. 이 결과를 공개 서비스의 공동 검수 완료로 표시하지 않는다.
