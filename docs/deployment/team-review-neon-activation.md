# 공동 검수 DB 활성화 승인 대기

2026-10-21 기준, 공동 검수의 코드와 격리된 PostgreSQL 검사는 완료됐지만 실제 운영 공간은 **0개**다. 앱의 DB 환경 변수도 등록하지 않았다. 이 문서는 실행할 변경을 구체적으로 검토하기 위한 자료이며, 활성화 완료 기록이 아니다.

- [PR #3](https://github.com/sokldjs554/toss-ads-ai-project/pull/3), 병합 커밋 `3e52e58b28175822a6b3f36a824f885a53adaede`

## 적용하려는 변경

대상은 이 프로젝트를 위해 준비한 Neon의 `preflight` 데이터베이스다. 기존 프로젝트나 광고 데이터의 삭제·초기화는 포함하지 않는다.

1. `preflight_team` 스키마와 상태 테이블, 초기 관리자 계정의 해시·요청 영수증을 만든다. 스키마나 같은 이름의 역할이 이미 있으면 중단하며 덮어쓰지 않는다.
2. 로그인용 `preflight_runtime`과 로그인할 수 없는 함수 소유자 `preflight_team_api_owner`를 만든다. 서버 계정에는 스키마 사용과 `lock_workspace`, `save_workspace` 두 함수 실행 권한만 준다. 테이블·열을 직접 조회하거나 수정하는 권한, 다른 역할 멤버십은 주지 않는다.
3. 키 인증·계정 변경·영수증·revision 검사를 수행하는 검증된 함수 7개를 설치한다. 본문 해시와 실제 권한이 기대와 같은지 같은 트랜잭션 안에서 검사한다. 임시 설치 권한은 회수한다.
4. 초기화가 확인된 뒤 서버 전용 연결 정보를 해당 Render 서비스의 `PREFLIGHT_TEAM_DATABASE_URL` 한 항목에 등록한다. 기존 환경 변수는 병합 방식으로 보존한다. DB 관리자 연결 정보는 서버에 등록하지 않는다.
5. 공개 서버에서 합성 광고 1개와 임시 검수 계정 2개로 저장·새 세션 복원·담당자별 화면·합성 결과 내보내기 제외를 확인한다. 시험 계정은 검증 뒤 비활성화하고 실제 사람 검수 건수는 0으로 유지한다.

스키마·역할·함수·초기 상태 생성은 51개 SQL 문장을 **한 트랜잭션**으로 실행한다. [비밀값이 없는 SQL 템플릿](team-review-neon-template.json)은 검증한 소스와 함수 해시를 고정한다. 비밀번호와 초기 상태는 전체 SQL literal 자리에서 안전하게 인용한다. 비밀번호가 채워진 SQL·요청 payload는 파일에 저장하거나 로그에 남기지 않는다.

## 승인이 필요한 이유

처음에는 서버용 비밀번호의 SCRAM 검증값만 전달하도록 준비했다. Neon은 이 요청에 `Neon only supports being given plaintext passwords` 오류를 반환했다. 직후 읽기 조회에서 스키마 없음·새 역할 0개를 확인했다.

[Neon 공식 역할 관리 문서](https://neon.com/docs/manage/roles#manage-roles-with-sql)는 SQL 계정 생성에서 원문 비밀번호를 제공해야 하며 미리 해시한 비밀번호는 지원하지 않는다고 설명한다. 따라서 Neon에 새 서버 계정을 생성하려면 **이 프로젝트용으로 새로 만든 난수 DB 비밀번호를 인증된 Neon 연결 도구에 전달**해야 한다. 기존 외부 모델 API 키를 보내는 작업이 아니다.

이 입력 형태로 바꾼 요청은 자동 승인 검토에서 거절됐다. 사유는 생산용 역할·권한을 지속적으로 만들면서 새 비밀번호 원문을 Neon에 전달하는 변경에 대해 구체적인 사용자 승인이 필요하다는 것이다. 해당 요청은 실행되지 않았다. 다른 API나 SQL 경로로 재시도하지 않았다.

승인 범위는 **새 서버용 DB 비밀번호를 Neon에 전달하여 위 제한 계정을 생성하고, 그 계정의 연결 정보를 지정한 Render 서비스에 등록하는 작업**이다. 승인 후에도 먼저 현재 DB 상태를 다시 조회하고, 이미 생성된 객체가 있으면 원인을 확인한 뒤 진행한다.

## 공개 자료와 비밀 자료

이 템플릿에는 실제 비밀번호, 접근키, DB 연결 URL, 초기 계정의 해시가 없다. 초기 관리자 접근키와 복구 요청 파일은 별도의 보호된 파일로 보관하고, 실제 DB 적용을 확인하기 전에는 활성 키로 전달하지 않는다. 외부 DB 제공자의 내부 감사·관리 기록까지 비밀이 남지 않는다고 보장하지 않는다.

## 이 변경으로도 증명하지 않는 것

서버 DB 연결은 실제 사람의 독립 검수, 광고주 트래픽 운영, 대규모 처리량을 증명하지 않는다. 또한 유효한 앱 키와 서버 DB 연결 정보가 함께 유출된 경우의 전체 블라인드 워크플로를 SQL이 재구현하는 것은 아니다. [권한 경계와 운영 절차](../TEAM_REVIEW.md)의 제한을 그대로 적용한다.
