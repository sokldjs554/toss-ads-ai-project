## 확인하고 수정한 문제

### 1. 업로드 크기 제한 안의 SVG가 정규식에서 오래 멈춤

SVG의 1 MB 제한만으로 실행 시간을 제한할 수 없었다. 다음 경로에서 같은 입력의 나머지를 반복해서 읽거나, 같은 숫자·공백 구간을 여러 반복 항목에 나누어 맞추는 역추적이 발생했다.

- `_CSS_BAD_DECL`: 위험 구문이 없는 긴 선언에서도 선언 앞부분을 매 위치부터 다시 탐색했다.
- `_CSS_URL`: 닫히지 않은 `url(`이 반복되면 각 시작점에서 끝까지 다시 탐색했다.
- `_CSS_COMMENT`: 끝나지 않은 주석 시작점이 반복되면 각 시작점에서 다시 탐색했다.
- `_LEN`: 숫자 반복과 선택적 소수부, 단위 앞뒤의 공백 반복이 겹쳤다. 끝에 잘못된 문자가 붙은 긴 길이 값에서 역추적이 커졌다.

회귀 테스트는 별도 프로세스에서 실행하고 5초 제한을 두었다. 기존 코드의 각 사례는 제한에 걸려 실패했다. 수정은 선언을 한 번씩 분리해 검사하고, URL의 읽은 구간을 다시 검사하지 않는 스캐너를 사용하며, 끝나지 않은 주석을 EOF까지 한 번만 소비하고, 길이 정규식의 중복된 반복을 제거하는 방식이다.

다음은 수정 후 Python 3.11.17에서 `load_image()`를 직접 호출한 단일 측정값이다. 공유 실행 환경의 참고값이며 운영 지연 보장이나 정식 성능 벤치마크가 아니다. 자동 테스트의 여유 있는 한도는 각 프로세스 5초이다.

| 입력 | 입력 바이트 | 수정 전 회귀 테스트 | 수정 후 직접 호출 |
|---|---:|---|---:|
| 무해한 긴 CSS 선언 | 900,066 | 5초 초과 | 0.0620초 |
| 닫히지 않은 속성 `url(` 반복 | 120,049 | 5초 초과 | 0.0092초 |
| 끝나지 않은 CSS 주석 반복 | 900,049 | 5초 초과 | 0.0203초 |
| 잘못된 접미사가 붙은 긴 숫자 길이 | 900,028 | 5초 초과 | 0.2576초 |
| 잘못된 접미사 앞에 긴 공백이 있는 길이 | 900,029 | 5초 초과 | 0.1495초 |

잘못된 길이에 기본 크기 300×150과 알림을 사용하는 기존 동작은 유지했다. 요소 수·깊이·`use` 확장 수·파일 바이트·픽셀 제한도 유지했다. XML 파서 자체가 원인이라는 증거는 이번 재현에서 얻지 못했다. 실제로 확인한 병목은 파싱 이후의 정규식 처리였다.

### 2. 불완전하거나 이스케이프된 외부 CSS 주소가 정화 결과에 남음

`style="fill:url(https://example.invalid/image.svg"` 및 같은 내용의 `fill` 속성에서 닫는 괄호가 없으면 기존 URL 정규식이 아무것도 제거하지 않았다. `fill`, `filter`, `clip-path`의 `u\72l(...)` 표기도 기존 속성 분기가 찾는 문자 그대로의 `url(`에 걸리지 않았다. 외부 주소가 정화된 SVG에 남는 것을 확인했다. 외부 리소스를 실제로 불러오는 브라우저 시험은 수행하지 않았다.

수정 후 불완전한 URL은 해당 스타일을 비우고, 외부 참조를 담을 수 있는 SVG 표현 속성에도 기존 CSS 정화 규칙을 적용한다. 제거 사실은 기존 `sanitized_notes` 경로로 알린다. 인용부호가 있거나 공백을 포함한 정상적인 내부 `#local` 참조는 보존하는 긍정 사례도 함께 확인했다.

### 3. 사용자 정의 배너 팔레트가 SVG 속성에 그대로 삽입됨

공개 `compose(..., palette=Palette(...))` 경로는 사용자 정의 색 문자열을 검증하지 않았다. 색 값에 속성 종료·`<script>` 문자열을 넣으면 실제 태그가 생성되었고, `url(https://...)`도 SVG에 남았다. 일반 화면은 정해진 팔레트를 선택하므로 이 재현은 사용자 정의 `Palette`를 사용하는 코드 호출 경계의 문제다.

배너를 만들기 전에 여섯 색 필드를 기존 `parse_color()`가 지원하는 색인지 확인하고, XML에 허용되지 않는 제어 문자가 있으면 `ValueError`로 거절하도록 수정했다. 제어 문자 사례도 먼저 실패를 확인했다. 정상적인 색 조합과 대비가 부족한 색 조합의 점수 계산은 유지한다. 대비 부족 자체를 생성 단계에서 거절하도록 바꾸지는 않았다.

## 소재 퀄리티 검토 결과

소재 퀄리티에는 이번 검토에서 새로 확인된 결함이 없다. 기존 테스트로 다음 경계를 확인했다.

- 같은 입력의 결정론, 계산할 수 없는 신호의 제외와 가중치 재정규화, 두 문구에서 공통으로 계산된 신호를 사용하는 비교.
- 빈 문구·공백·이모지·영문·긴 문구·여러 고지 문구에 대한 계산과 표시.
- 심사 판정과 퀄리티 점수의 모듈 분리, 화면 출력의 HTML 이스케이프, 세션 캐시와 계산 실패 시 화면 처리.
- 저장된 평가 결과와 동결 기록의 기존 검증.

신호·가중치·단어 목록·무승부 기준을 조정하지 않았다. `core/creative_quality.py`는 기준 커밋과 바이트가 같고 SHA-256은 다음과 같다.

```text
308df411f3adaa4c5810f58d4a8db4c46494aa0ccec2b5c2106b746006564e26
```

최종 확인용 데이터, 저장된 평가 보고서, 실제 모델의 과거 벤치마크 숫자를 수정하지 않았다. 규칙 작성자 한 명의 합성 사례라는 한계와 실제 모델·실제 광고 성과를 측정하지 않았다는 한계는 그대로다.

## 변경 파일과 남는 한계

실행 코드 변경은 `core/images.py`, `core/banner.py` 두 파일이다. 회귀 테스트는 `tests/test_image_sanitizer_bounds.py`와 `tests/test_image_banner.py`에 있다. UI 구성이나 이미지·문구의 판정 합산 규칙은 바꾸지 않았다.

SVG 정화가 모든 브라우저 동작의 안전성을 보증하는 것은 아니다. 이번 검토는 위에서 직접 재현한 실행 시간·출력 경계에 한정했으며 전체 CSS 문법 분석기나 이미지 디코더를 추가하지 않았다. 래스터 이미지 내부 글자·의미의 정확도, 도형으로 그린 글자, 실제 글꼴의 폭, 광고 성과와 점수의 관계에 관한 기존 한계도 남아 있다.
