## 구현과 실제 결과

RAG는 관련 정책과 입력 상품 사실을 검색하고 실제 모델이 출처를 인용한 의견을 생성한다. 검색은 문자 bigram 기반이며 벡터 RAG라고 부르지 않는다. 출처 ID·원문 연속 구절·정책/상품 근거 종류를 코드로 검사한다. 정확한 인용 존재와 의미적 타당성은 별개다.

도구 경로는 실제 모델이 수정안을 만들고 `check_policy`를 호출한다. 코드 검사 결과를 tool 응답으로 받고 종료/수정을 선택하며 최종 RAG 검토를 재사용한다. 최대 4 API 호출·2회 수정, 미해결/실패는 보류하고 사람이 판단한다. 같은 프롬프트 입력만 바꾼 두 기능이 아니다. 모델이 코드 반려를 승인으로 덮어쓰지 않는다.

## 실패와 비용도 포함한 원장

자동 계정 서버 누적 예약 $1.04(사람 $0.16 포함 총 $1.20), 전체 예약 한도 $1.50, 계정 $0.60, 요청 $0.08. 실패 예약을 환급하지 않았다. 제공자 계정 전체의 청구 상한을 보장한다는 뜻이 아니다. SDK 재시도 0·호출 30초 제한. 실패하면 DEMO로 대체하지 않는다.

v1 원래 네 입력 중 인용 누락 3/4가 v2에서 0/4가 됐지만 최종 판정은 모두 동일했다. 최소 구매 조건 동일 입력은 v2 인용 불일치→v3 제공자 실패→v4 사람 검토 대기로 바뀌었다. 실제 진단은 strict enum의 줄바꿈 거부 HTTP400이었다. v4는 제어문자 없는 원문 연속 구절을 source ID에 묶어 선택하도록 수정했다. 원문을 합치거나 실패한 인용을 사후 교체하지 않는다. 기존 쿠폰 도구 두 사례의 model_hold는 v4에서 재검증하지 않았으므로 해결됐다고 주장하지 않는다.

이 자료는 개발/운영 연결 검증이다. 결과를 본 사례를 독립 holdout이라고 부르지 않는다. 자동 인용 대조가 독립 사람 정답이나 정책 정확도를 대신하지 않는다.
