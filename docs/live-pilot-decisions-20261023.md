# LIVE 연결의 기술적 판단과 실패 근거

기준 커밋 `7767dcbe288fd9ceaf6b9fdc021f7ac4450ad388` 이후 작업이다. 사용자 요구·승인과 AI가 설계·구현·실행한 작업을 분리해 읽는다. 지원서 문안이 아니다.

| 문제 | 검토한 대안·선택 이유 | 코드·검증 | 한계 |
|---|---|---|---|
| 기존 전체 정책 프롬프트를 RAG라고 부를 수 없음 | 기존 카탈로그를 업종 필터하고 한글 문자 bigram 관련도로 정책 6개·상품 사실 4개를 검색. 벡터 DB 도입 없이 현재 작은 카탈로그를 활용 | [검색·인용 검사](../agents/live_pilot.py), 검색 결과 ID·본문·버전·SHA256 저장 | 검색 recall·관련성의 독립 평가 없음. 점수는 의미 유사도의 보장이 아님 |
| 같은 코드 주도 수정 경로를 두 번째 LLM 방식으로 재명명하면 근거 부족 | 실제 모델 function call을 받아 `check_policy` 실행, 결과를 tool 메시지로 반환. 모델이 다음 수정/종료를 선택하고 마지막 RAG 검토와 사람 승인으로 연결 | [run_workflow](../agents/live_pilot.py), 실제 저장된 `tool_call_id`·수정안·검사 결과 | 최대 수정 2회·호출 4회. 실제 광고 게시 기능 없음 |
| v1 응답 3/4에서 필수 정책/상품 인용 누락 | 프롬프트 강화만으로 해결하지 않고 v2 JSON Schema에서 정책과 상품 인용 필드를 각각 필수화 | v1/v2 동일 네 입력 해시 대조, 누락 3/4→0/4 | 최종 판정 네 건 모두 동일. 도구 두 건은 모델 HOLD로 남음. 정책 정확도 개선 주장은 불가 |
| v2 별도 사례의 자유 인용문이 검색 원문과 달라 보류 | v3는 source ID와 정확한 전체 passage를 한 schema 선택지로 묶어 모델이 선택. 사후 인용 대체·검증 완화는 하지 않음 | [review_format](../agents/live_pilot.py), [수정 전 실패](evidence/live-pilot-20261023/passages-red.txt), 실행 전 고정 2건 계획 | 의미적 지지는 별도 사람 판단. v2 별도 사례는 v3 개발 비교 자료로 전환했음을 명시 |
| v3의 전체 원문 enum이 제공자에서 거부됨 | 별도 1회 진단으로 strict enum의 줄바꿈 금지 확인. v4는 원문의 제어문자 없는 연속 구절을 ID에 묶고 전체 검색 원문을 보존 | [HTTP 400 진단](evidence/live-pilot-20261023/schema-diagnostic-39996868624.json), [회귀 red](evidence/live-pilot-20261023/live-control-red.txt), [구현](../agents/live_pilot.py) | 원래 서버 실패의 상세 HTTP 응답은 미보존. 후속 진단 재현과 구분하며 비용 미확인 유지 |
| 유료 호출 중복·실패에 의한 미기록 지출 | PostgreSQL 트랜잭션 예약→호출 시작 기록→SDK(retry 0)→사용량·종료 저장. 동일 payload는 재접속/버전 변경 후에도 기존 결과 재사용 | [영속 장부](../ops/live_pilot_store.py), [SDK 경계](../llm/live_pilot_gateway.py), [DB 동시성 테스트](../tests/test_live_pilot_store.py) | 제공자 전체 계정 청구 제한 아님. 결과 불명은 예약을 유지하며 자동 재시도하지 않음 |
| 기존 공동 검수 자료 보호 | 별도 스키마와 제한 DB 역할·시험 계정. 원문은 인증된 작업 데이터, 일반 운영 export에는 원문·프롬프트·키 제외 | DB 권한 확인, 타 계정 조회/쓰기 거부 테스트, 공개 브라우저 계정 분리 | 운영 DB 관리자까지 격리하는 구조는 아님. 자동 시험을 사람 사용으로 세지 않음 |
| 브라우저가 Streamlit 입력 반영 전에 실행 | 모든 입력값·경로가 고정값으로 반영됨을 기다린 뒤 실행, 조회는 해당 요청 ID가 표시된 뒤 검사 | [공개 브라우저 검증](../scripts/verify_live_pilot_ui.py), 실패 Actions와 후속 실행 모두 보존 | 단순 UI 대기 실패와 제공자 실패·실제 모델 HOLD를 분리. 확인하지 못한 서버 준비 지연 원인 단정 안 함 |

현재 결과는 [최신 상태](live-pilot-final-status-20261023.md)와 [원장](live-pilot-structured-20261023.md)을 확인한다. 테스트 기대값은 연결·경계 검증이며 사람이 판정한 독립 정책 정답이 아니다.

사용자가 확인한 기여: 목표·우선순위·기존 한계 보존 지시, 금지어 삭제 지시, 유료 API 실행 승인, Render 키 등록, 제한 DB 자격증명의 Render 저장 승인, 새 미사용 DB 역할 삭제 승인. 이번 구현·테스트·자동 브라우저·배포 조작·기술 문서 작성은 AI 지원 작업이다. 사용자의 직접 코딩·새 LIVE 경로 직접 수행은 별도 확인이 필요하다. 커밋 작성자 이름만으로 직접 구현했다고 판단하지 않는다.

## 실제 사용에서 발견한 저장 안내 혼동

본인 1명이 두 경로를 사용한 뒤 저장했다고 응답했지만, 최초 운영 JSON과 서버에는 사람 판단 감사가 없었다. 기록 자동 저장과 판단 저장을 구분하고 선택 후 열기 버튼을 안내하자 도구/RAG 각 승인1건이 저장됐다. 대신 승인하거나 기존 감사를 수정하지 않았다. `ui/live_pilot_view.py`에 미저장 사람 판단 안내와 기록 선택 후 열기 안내를 추가했다. 기능 흐름·권한·판정·모델 호출은 바꾸지 않았다. 관련 기존 UI/엔진/게이트웨이 테스트31개 통과. 이는 한 사람의 안내된 사용에서 발견한 혼동이며 일반 사용성 개선율로 계산하지 않는다.
