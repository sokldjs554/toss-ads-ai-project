첫 추가 실행 요청은 [features-20261021-run1](../evals/live_request_20261021.json)이다. 호출 전에 소스·입력 지문과 계획 수를 검사하고 예약을 원격 브랜치에 기록한다. **한 실행 상한 $2·300회, 이번 추가 평가 전체 예약 상한 $4**이며, 기존 $10 예약 장부는 그대로 보존한다. 실제 사용량이 작아도 이전 예약을 재사용하지 않는다. 중단·불완전 실행 역시 기록을 남긴다.

## 4. 사람 검수와 공동 저장의 경계

[독립 검토용 자료](human-review/quality-20261021/reviewer-packet.zip)에는 28개 문구 쌍을 섞고 좌우 순서를 바꾼 자료와 **빈 라벨 CSV**를 넣었다. 정답 대응표는 검토자 ZIP 밖에 분리했다. 가져오기는 자료 지문과 필수 확인 항목을 검사하지만, 실제 신원·독립성을 확인했다고 표시하지 않는다. **실제 사람의 제출은 아직 0건**이다.

개인 대기열은 같은 브라우저의 IndexedDB에 저장한다. 새 공동 검수 화면은 Render 서버에서 PostgreSQL을 사용하도록 구현했다. 관리자는 광고·담당자를 관리하고, 검수자는 자신이 배정받은 항목에 답하며, 조정자는 판정이 갈린 항목을 별도로 검토한다. 키를 바꿔도 담당자 ID는 유지한다. DB 장애에서 브라우저 저장으로 몰래 바꾸지 않는다.

관리자 CLI는 새 접근키와 요청 ID를 보호된 파일에 먼저 내구성 있게 저장한 뒤 DB를 변경한다. DB 저장 뒤 응답을 잃어도 같은 파일로 재시도한다. 파일 동기화가 실패한 재시도에서 먼저 DB를 바꾸던 결함을 독립 검토로 재현한 뒤 수정했다. 복구는 명시적인 DB 관리자 경로이며 기존 대기열·다른 계정·기록을 보존한다. [관리자 운영 문서](TEAM_REVIEW.md), [독립 회귀](../tests/test_team_review_admin_review.py).

실제 운영 DB 초기화 시도는 서버 역할에 인증 상태까지 직접 수정할 수 있는 권한을 주는 범위 때문에 자동 승인 검토에서 차단됐다. 그 시도에서는 DB 변경을 적용하지 않았다. 현재는 지정 함수 실행만 허용하는 더 좁은 권한 경계를 구현·검증 중이며, 운영 연결 완료로 주장하지 않는다.

## 5. 검증과 배포 기록

최종 CI의 실제 PostgreSQL 검사, 현재 소스의 브라우저 확인, 실제 API 결과 화면과 공개 Pages·Render 배포를 확인한 뒤 커밋·실행 링크·범위를 기록한다. 로컬 서버와 로컬 정적 빌드의 결과를 공개 서비스 검증으로 확대하지 않는다.

첫 기능 체크포인트 `3887041`의 [CI 39557214734](https://github.com/sokldjs554/toss-ads-ai-project/actions/runs/39557214734)는 **4,241개 통과, 415.84초**였고 회귀 게이트와 앱 시작 검사도 성공했다. 당시 실제 PostgreSQL 동시성·응답 유실·관리자 복구 검사를 포함한다. 이후 추가 중인 제한 DB API의 검증 결과까지 이 숫자에 포함시키지 않는다.

제한 DB API의 첫 체크포인트 `fb33d30`의 [CI 39559208081](https://github.com/sokldjs554/toss-ads-ai-project/actions/runs/39559208081)는 **4,238개 통과·1개 실패·40개 준비 오류**였다. 내부 함수명 `_api_stamp` 등의 첫 밑줄을 설치 코드가 거부해 PostgreSQL 검사 준비가 실패했다. 이 오류가 있는 실행은 DB 검증 성공으로 세지 않는다. 별도 한 실패는 이미지 결과의 사용자 문구를 ‘일치합니다’로 고친 뒤 기존 기대 문구가 남은 검사였다. 함수명 검사는 함수 경로에만 밑줄을 허용하고 스키마·역할 이름의 제한은 유지하는 회귀로 수정한다. 실패 실행은 이후 통과 결과와 함께 보존한다.

다음 `a0670248`의 [CI 39568241475](https://github.com/sokldjs554/toss-ads-ai-project/actions/runs/39568241475)는 **4,257개 통과·23개 실패**였다. 설치·권한 확인까지 진행됐지만, 정상 계정 생성 시 저장 함수의 영수증 차이 계산에서 JSON 연산자 우선순위 문제가 드러났다. 이 실행도 배포 근거로 사용하지 않았다. 실제 DB 본문 오류를 긴 UI 검사보다 먼저 발견하도록 제한 API 검사를 CI의 앞부분에 추가했다. 이후 전체 검사는 그대로 유지한다.

영수증 식을 수정한 `e3fe8994`의 [CI 39570126565](https://github.com/sokldjs554/toss-ads-ai-project/actions/runs/39570126565)는 앞부분의 DB 검사에서 **37개 통과·1개 실패, 5.22초**였다. 기존 정상 저장·권한·변조 거절 검사는 통과했고, 새 연속 저장 회귀가 같은 담당자 이름을 두 번 발급하려 해 정상적인 중복 이름 차단에 걸렸다. 두 시험 계정의 이름을 구분하고 영수증 보존 조건은 유지했다. 이 실행의 전체 스위트는 시작하지 않았으므로 전체 통과로 표시하지 않는다.

새 실호출 기록 화면은 [native·Pages × 데스크톱·모바일 재검사](evidence/remaining-20261021/live-run1-native-pages-recheck/README.md)에서 **185개 확인, 실패 0개**였다. 품질 채택·보류와 보조 평가의 별도 분모, 현재 성과 회귀와 남은 작은 하락 7/12까지 원본과 대조했다. 이는 로컬 서버·정적 빌드 검증이며 공개 서버 DB 접속 성공을 뜻하지 않는다.

이미 저장된 중간 증거는 [이번 브라우저 검증 디렉터리](evidence/remaining-20261021/README.md)에 있으며, 실패한 첫 시도도 보존한다. 기존 테스트 수를 새 기능을 모두 포함한 최종 테스트 수로 사용하지 않는다.

## 6. 이 프로젝트로 아직 증명하지 못한 것

- 실제 광고주 트래픽에서의 운영 기간, 생성 시간 절감, 승인율·클릭률·전환 개선.
- 실제 사람의 독립 검수 결과와 선호 일치. 여러 시험 계정으로 확인한 기능 동작은 이 실적을 대신하지 않는다.
- 새로운 생성기·현실 데이터에서 작은 성과 변화를 찾는 능력과 실제 원인 증명.
- 일반 상품 사진·동영상 전체의 시각 정책 판단. 고정 글자 배너 사례의 결과를 모든 이미지로 확장하지 않는다.
- 큰 검수 조직의 처리량과 지연. 공동 저장은 한 검수 공간의 상태 행을 잠그는 소규모 설계이며 별도 처리량 측정 전 성능을 주장하지 않는다.

이 항목들은 임의의 숫자나 성공 라벨을 추가해 해결할 수 없다. 이력서에서는 구현·측정한 범위와 앞으로 수집해야 할 실사용 근거를 구분한다.
