# 수동 검수와 무료 DEMO 비교 규약

기존 [사람 측정 절차](../strengthening-human-protocol-20261023.md)의 입력·배정을 재사용한다. 이 문서는 2026-10-24 이후 진행할 측정의 조건을 구체화하며 과거 실험 결과가 아니다. 현재 완료 응답0건이다.

- 도구 조건: 공개 Pages의 **무료 DEMO**, 실제 모델 호출 없음. LIVE·replay 결과를 섞지 않는다. 화면 버전과 입력 해시를 기록한다.
- 대조 조건: 같은 정책 문서·상품 사실·광고 원문을 보고 수동 검수. 검색·다른 AI·Preflight 결과 조회를 사용하지 않는다.
- 자료: [A/B 각6개 입력](../evidence/strengthening-20261023/participant-inputs.json), [기존48행 배정 양식](../evidence/strengthening-20261023/human-workflow-measurement.csv). 48행은 **4명×12작업의 빈 계획**, 응답48개가 아니다. 먼저 4명 균형 배정을 목표로 하되 미확보 시 그대로 미완료로 남긴다. 2명으로 절차만 시험하면 불균형 탐색 자료로 별도 기록한다.
- 분리: R14 반복 LIVE 입력과 기존 28쌍 선호 평가를 이 측정에 넣지 않는다. 개발·공개 저장소의 입력을 재사용하므로 독립 신규 holdout이 아니다.

## 사람이 해야 하는 준비

1. 채점 기준 검수자는 [초안 라벨을 뺀 검수표](reviewer-blind.csv), 원문·사실 및 [정책](../../guardrails/policy.yaml)을 받는다. 각 광고의 최종 판정, 위반 단위 목록, 원문 구절·규칙·이유를 먼저 적는다. 초안 라벨이나 코드 결과를 이미 봤다면 노출 사실을 남긴다. 정책 파일·입력은 공개돼 있어 맹검을 기술적으로 강제하지 못한다.
2. AI 초안은 사람 최초 판단 저장 뒤 참고한다. 미합의 항목을 보류하고, 원본 AI 초안은 수정하지 않는다. 사람 기준을 별도 버전으로 저장하고 해시·검수일·검수자 역할을 고정한 뒤 측정을 시작한다. 현재 [frozen-plan.json](frozen-plan.json)은 입력과 기존 초안의 고정만 증명하며 사람 정답 완성을 뜻하지 않는다.
3. 측정 참여자는 정답 검수자·제작자와 분리한다. 사람에게 전달할 때는 입력과 배정 행만 제공한다. 사전 노출 여부를 기록하고 기존 평가 참여 경험도 함께 남긴다. 외부 연락은 사용자가 한다.

## 실행과 채점

### 원문을 그대로 검사하는 기존 DEMO 조작

메인 화면의 `요청 내용`은 광고 원문 검사 칸이 아니라 **광고 생성 요청**이다. 여기에 평가 원문을 넣고 생성된 광고를 채점하면 실험이 달라진다. 다음 순서를 두 조건 모두의 사전 설명에서 제공한다.

1. 사례마다 새 비공개 브라우저 세션에서 Pages `/app/`을 연다. 이전 반려 이력·사실·재검사 상태를 재사용하지 않는다. API 키는 넣지 않는다.
2. 상품명 `합성 상품`, 업종 `커머스`, 상품 설명·랜딩 문구는 빈칸, 사실 목록은 해당 사례 facts의 text만 한 줄씩 넣는다. facts가 없으면 비운다. 요청 내용은 모든 사례에서 `상품 정보를 알리는 짧은 광고 문구를 만들어 주세요.`로 고정한다. 모드 `예시 실행`·실제 호출 없음 표시를 확인한 뒤 **광고 초안 만들기**를 누른다. `예시로 바로 실행`은 선택한 예시의 사실로 덮어쓰므로 사용하지 않는다.
3. 생성된 첫 광고안의 `문구 고쳐서 다시 검사`를 연다. **제목은 case.headline 그대로, 본문·버튼 문구·안내 문구는 모두 빈칸**으로 덮어쓰고 `수정한 문구 다시 검사`를 누른다. 초기 생성 광고·자동 수정안은 평가 대상이 아니다.
4. 재검사 영역의 **검사한 문구**가 고정 원문과 일치하고 사실이 동일한지 확인한다. 이 확인이 안 되면 실행을 중단하고 절차 오류로 기록한다. 이후 원문 위반 확인·직접 수정·재검사를 수행하고 최종 문구를 제출한다. 원래 `광고안` 카드의 판정과 재검사 판정을 섞지 않는다.

수동 조건도 같은 상품명·커머스·빈 본문/버튼/고지와 동일한 facts를 제공한다. DEMO의 준비·복사·입력 시간도 총 시간에 포함한다. 이 절차는 기존 화면을 이용하는 우회 조작이므로 준비 부담을 숨기지 않는다. 참여 전 연습 두 건으로 조작이 가능한지 확인하고, 불가능하면 본 측정을 시작하지 않는다. 현재 신규 참여자의 이 절차 실행은 미확인이다.

기존 네 배정(수동A→DEMO B, DEMO A→수동B, 수동B→DEMO A, DEMO B→수동A)을 순서대로 배정하고 결과를 보고 바꾸지 않는다. 각 사람은 동일 원문을 한 번만 본다. 연습은 평가에 없는 두 광고로 동일하게 제공하며 시간 집계에서 제외한다. 예: 사실·문구 모두 용량200ml, 사실 용량200ml인데 문구250ml인 합성 컵. 연습 노출은 기록한다.

문구와 자료가 처음 보일 때 시작, 최종 판단·문구 제출 때 종료한다. 사례당2분 상한, 원래 입력을 받은 시점부터 수동 입력·도구 대기·재검사까지 포함한다. 자동 실행/API 지연만으로 사람 작업 시간을 대신하지 않는다. 중단·실패·한도 초과는 행을 유지하고 완료0·상한시간·사유를 남긴다. 시간은 완료자 중앙값/분포와 전체의 완료율·제한시간까지 걸린 시간을 함께 보고한다.

참여자는 최종 판정, 발견한 위반 단위, 수정 문구를 별도 비공개 응답 파일에 제출한다. 채점자는 사용 조건을 가린 응답으로 미리 고정된 사람 기준과 대조한다. **놓친 위반 단위/전체 정답 위반 단위**, **위험한 통과 광고/위반 광고**, **잘못 반려·수정 요구한 광고/정상 광고**, **보류 광고/전체 광고**, 수정 후 남은 위반, 수정 횟수를 각각 보고한다. 원래 CSV의 missed_violations·false_reject에는 이 정의를 사용하고 분모와 보류는 별도 채점 파일에 남긴다. 애매해 정답에서 제외한 사례도 ID·이유·개수를 공개한다.

작업당 원자료와 사람별 조건 차이를 보존한다. 작은 표본의 평균 개선율을 전체 사용자 효과로 일반화하지 않는다. 오류가 증가하면 시간만 빨라졌다는 이유로 개선으로 결론 내리지 않는다. 새 버전 배포가 끼면 동일 비교 블록을 중단하고 버전을 나누어 보고한다. 결과를 본 뒤 유리한 행을 삭제하거나 채점 기준을 바꾸지 않는다.
