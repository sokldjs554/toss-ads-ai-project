# 반복 사용과 효과 측정 준비

2026-10-24 KST 작성. 기존 기능으로 **2주 관찰 기간의 최소 반복 사용**, **무료 DEMO와 수동 검수 비교**, **격리 실패 대응 검증**을 진행한다. 기간 경과나 새 사람 참여를 미리 완료로 세지 않는다. 상용 운영·장기 효과·채용 요건 충족은 이 계획의 완료만으로 입증되지 않는다.

기준 main은 `117d996e01b6a50d933a90f096238a4ab2160fd2`다. 기존 사람 평가 2명(현직자1·비전문가1, 28쌍×2=56응답)과 LIVE 본인1명·2건은 별개다. 기존 평가자에게 연락하거나 참여했다고 간주하지 않는다.

## 1. 본인이 할 최소 행동

[서버 LIVE](https://preflight-toss-ads.onrender.com/?view=LIVE%20검토)에 기존 개인 접근키로 접속한다. 키는 [개인 접속 안내](https://chatgpt.com/space/page_090da94f22408191b9abe204e3151138)에서 확인하며 채팅·CSV에 적지 않는다.

| 제안 날짜 KST | 작업 | 고정 입력 |
|---|---|---|
| 10월24일 | RAG 한 건을 직접 검토·판단·저장 | R14-01 |
| 10월30일 | 도구 수정·재검사를 직접 검토·판단·저장 | R14-02 |
| 11월6일 | 다른 입력의 도구 경로와 저장 기록 재접속 확인 | R14-03 |

입력은 [세션 입력 JSON](live-session-inputs.json)에 있다. 오늘 첫 작업은 RAG 경로를 선택하고 LIVE 제목 **보온병 용량 안내**, LIVE 본문 **용량 450ml 스테인리스 보온병입니다.**, LIVE 버튼 문구 **상품 보기**, 상품 근거 **이 상품은 용량 450ml 스테인리스 보온병입니다.**를 입력한다. LIVE 고지는 비워 둔다. JSON의 상품명은 사례 설명이며 실제 LIVE 폼에는 상품명·업종 입력란이 없다. 서버는 상품명을 `합성 파일럿`, 업종을 커머스로 고정한다.

각 날짜에 직접 시작·종료 시각을 기록하고, 검색된 원문과 인용·수정안을 읽는다. 인용이 원문에 존재하는지와 결론을 뒷받침하는지는 따로 판단한다. 본인 판단과 사유를 저장하고 `검토 저장됨`을 확인한다. 로그아웃·재접속 후 해당 요청을 선택하고 **선택한 기록 열기**를 눌러 판단까지 남았는지 확인한다. JSON과 [usage-log.csv](usage-log.csv)를 비공개로 전달한다. 저장 버튼이 없거나 보류면 그 상태를 남기며 승인을 만들기 위해 반복 실행하지 않는다.

시작이 늦으면 실제 시작일을 기준으로 1·7·14일 차에 배치하고 계획 변경을 기록한다. 자동 알림이나 상시 모니터는 설정하지 않았다. 이 세 번은 짧고 드문 합성 작업 관찰이며 고객 트래픽·매일 사용·장기 운영이 아니다. 기존 두 작업은 과거 기준 기록으로 유지하고 신규 작업 수에 넣지 않는다.

## 비용과 중단 조건

읽기 전용 DB 확인 시 기존 누적 예약은 전체 $1.20, 본인 $0.16이었다. 한도는 전체 $1.50·계정 $0.60·요청 $0.08이다. 따라서 다른 실행이 없으면 **신규 최대3요청, 추가 예약 최대$0.24**, 요청당 최대4호출이므로 최대12제공자 시도다. 정확한 모델은 `gpt-4o-mini-2024-07-18`, SDK 자동 재시도0, 호출 제한30초다. 기존 실제 소형 입력의 관측치로 세 건 비용을 대략 $0.003–$0.01로 계획하지만 응답·토큰에 따라 달라지며 예약액과 청구액은 다르다. 실패 비용이 미확인이면 0으로 적지 않는다.

이 준비에서 새 유료 호출은 하지 않는다. 사용자가 승인한 실제 API 사용 범위로 이후 직접 실행한다. 추가 수정·재검사도 새 입력이면 예약1건을 쓸 수 있으므로 세 건 한도 안에서 세션을 대체한다. 초과 실행·자동 재시도·한도 증액은 하지 않는다. 다른 계정이 예산을 사용하면 다음 세션을 멈추고 기록한다. 조회·동일 입력 재사용은 새 모델 작업으로 세지 않는다. 계정의 확인된 만료일은 11월22일21:44 KST이며, 공유하지 않는다.

## 2. 업무 효과 비교는 별도 DEMO 실험

[효과 측정 실행 규약](measurement.md)을 따른다. 기존 A/B 입력·네 배정 순서를 재사용하며 무료 DEMO를 한 가지 도구 조건으로 고정한다. 이 결과로 LIVE LLM의 시간 절감을 주장하지 않는다. 정답 검수·실제 참여 전에는 결과를 계산하지 않는다. 제작자는 운영 파일럿에 참여할 수 있지만 독립 효과 측정 표본에 합산하지 않는다.

## 3. 실패 대응과 채용 근거

[실패 대응 기록](failure-drill.md)은 모의 제공자와 실제 격리 PostgreSQL을 구분한다. [주장 검증표와 경쟁 서비스 비교 범위](claims-and-comparison.md)는 직접 확인한 동작만 기술하고 채용팀의 판정을 대신하지 않는다. [incident-log.csv](incident-log.csv)는 실제 장애와 훈련을 나누어 적는다. 민감 원문·키·개인 연락처는 공개 자료에 넣지 않는다.

사용자 역할은 요구사항·우선순위·승인·직접 사용·판단이다. 코드·테스트·자료 준비는 AI 지원 작업이다. 새 참여자와 별도 채점자는 아직 미확정이며 사용자 연락이나 고객 모집을 대신 수행하지 않았다.
